# 提炼速览与外部评审（去代码版）

> 来源：另一智能体对 **Desktop 上旧副本** 的通读评审（2026-09-20）。本文件做了两件事：
> ① 把评审中涉及命令、代码、平台路径的部分改写成**自然语言或伪代码**；
> ② 按本机**储存库（技能唯一来源）**的真实状态，更正已过时的判断。
> 权威定义仍在 [记忆制度](记忆制度.md)、[交流协议](交流协议.md)、[工具与脚本](工具与脚本.md)、
> [隐私与密钥](隐私与密钥.md)；这里只记"评审怎么看、哪些已经改"。

## 一、评审给的一句话定位

一套给"人 + AI 协作"用的**本地记忆与知识管理脚手架**：用固定目录结构 + 约定 + 体检脚本，
把"该记住什么、记在哪、怎么不泄密、怎么不腐烂"制度化；目标是**新开一个工作区就能开局体检全过**。

## 二、评审的几条结论（附现状更正）

| 评审结论 | 现状 |
| --- | --- |
| "模板文件没进 kit"是缺漏 | **更正：不是缺漏。** 本机版本的 `templates/` 是齐的（六区 README、`AGENTS.md`、settings、exchange、薄壳模板），铺开时由 `bootstrap.sh` 落地，内容再由 agent 填 |

## 三、唯一硬伤：跨平台（已修；修法用自然语言/伪代码描述）

问题：机器段落原来靠两条平台专有命令 —— 一条列分区容量、一条列块设备。在非 Linux 平台上，
前者会指向"另一个根"，后者干脆不存在；**脚本不崩，但数字静默失真** —— 这比报错更危险，因为它看起来正常。

修法（伪代码）：

```
采集「工作区所在分区」的容量（伪代码）
    锚点 ← 工作区路径所在分区的锚（Linux 是 /，Windows 是 C:\ 这类）
    用宿主语言标准库读取锚点的 可用 / 总 容量
    换算成人读单位，并给出已用百分比
    读不到 → 输出「探测不到（锚点不可用）」
    ※ 全程不调用平台专有命令

采集可移动 / 非系统设备（伪代码）
    若 平台 = Linux：调用块设备列表命令；命令不存在 ⇒ 视为「探不了」
    若 平台 = Windows：枚举盘符，跳过系统盘，逐个读容量
    其它平台：不猜
    「探不了」与「列表为空」是两个不同状态，必须分开返回
    由展示层把「探不了」写成一句自然语言说明
```

落地在 `scripts/state_snapshot.py`。因此 `STATE.md` 的机器段落在任何平台都"读得到、且不会静默失真"：
显示"本平台不自动探测"是**如实告知**，不是故障。

## 四、本机补做的验证（评审当时没能跑的那条链路）

- 铺开一个新工作区 → 体检 → 生成状态快照 → 建一次交流测试：**退出码全 0**；
- 新工作区体检唯一 ⚠️ 是"热记忆定位未填"，补上即全绿；
- 技能自身敏感串自检 ❌0；
- 三平台模拟：Linux 正常探测；macOS / Windows 的"探不了"路径输出自然语言说明，**不给错数**。

## 六、后续修订（v1.5.0，2026-10-02）

来源：**在一台真实机器的项目管理整顿之后**回填的 —— 那次踩到的不是"制度写得不够"，而是"制度没跟上实际形态"。

| 改了什么 | 为什么 |
| --- | --- |
| 项目区新增**两种形态**：`embedded` / `card`（一处真身 ＋ 登记卡，真身在工作区外） | 旧写法默认"项目就长在 `projects/` 里"，而实际用法是**工作区当控制台、项目真身在外盘**；旧"工作区干净镜像"机制因此必然漂移 |
| 体检新增 `cards` 项：核对**卡 ↔ 真身**（卡在不在、路径指不指得到、字段全不全、卡长不长、有没有漏登记的真身） | 卡制度最大的风险是"卡与真身对不上"，这是结构问题，机器能查 |
| **判断类的事（建不建、发不发、退不退役）写成自然语言建议**，不进脚本 | 判断没有唯一答案；写成硬校验只会逼人绕过它。判断归人，形式归脚本 |
| 隐私篇新增**可见性分级与推送闸门**（默认仅本机／默认 private／公开要人点头／按提交扫历史） | 旧文只讲"别把 Key 写进去"，没讲"什么时候可以外发" |
| `bootstrap.sh` 补 `--projects-mode` / `--truth-root`，并修正生成的 `[limits]`（原来把硬上限写成 150，与"150 触发、200 硬顶"的规则不一致） | 脚手架是**移民**第一课：铺出来的配置和规则不一致，后面所有工作区都跟着错 |

> 这一版也顺势把几个"只写在某台机器上"的经验（改名要动四处、已有远端仓库要接历史而不是另起）
> 提炼成**通用建议**，放进 [项目管理](项目管理.md)。
