# 提炼速览与外部评审（去代码版）

> 来源：另一智能体对 **Desktop 上旧副本** 的通读评审（2026-09-20）。本文件做了两件事：
> ① 把评审中涉及命令、代码、平台路径的部分改写成**自然语言或伪代码**；
> ② 按本机**储存库（技能唯一来源）**的真实状态，更正已过时的判断。
> 权威定义仍在 [记忆制度](记忆制度.md)、[交流协议](交流协议.md)、[工具与脚本](工具与脚本.md)、
> [隐私与密钥](隐私与密钥.md)；这里只记"评审怎么看、哪些已经改"。

## 一、评审给的一句话定位

一套给"人 + AI 协作"用的**本地记忆与知识管理脚手架**：用固定目录结构 + 约定 + 体检脚本，
把"该记住什么、记在哪、怎么不泄密、怎么不腐烂"制度化；目标是**新开一个工作区就能开局体检全过**。

## 二、评审的几条结论（附现状更正）

| 评审结论 | 现状 |
| --- | --- |
| "模板文件没进 kit"是缺漏 | **更正：不是缺漏。** 本机版本的 `templates/` 是齐的（六区 README、`AGENTS.md`、settings、exchange、薄壳模板），铺开时由 `bootstrap.sh` 落地，内容再由 agent 填 |
| 跨平台残缺是唯一硬 bug | **成立，已修**（见第三节）。与模板是否预置无关，是脚本真实问题 |
| 过度工程化风险（六区 + 三层 + 体检 + 协议状态机对"单人 + AI"偏重） | **保留为观察**：它是 agent 每会话的**遵循成本**，不是磁盘负担。用着顺就是对的，但别指望零成本自动生效 |
| 其它技能写死了本机坐标（代理端口、面板端口、盘符路径），与"事实只写一次"矛盾 | **降级为提醒**：那些是**内容**，本 kit 是**框架**。可照做的办法：本机坐标一律进 `memory/settings.md`（半稳定事实区），生成其它技能内容时也不写死 |
| 评审方"没跑起来" | 是它的**环境限制**：它的命令环境看到的是空 stub，读不到真实目录。这不构成 kit 的问题；本机已补做（第四节） |

## 三、唯一硬伤：跨平台（已修；修法用自然语言/伪代码描述）

问题：机器段落原来靠两条平台专有命令 —— 一条列分区容量、一条列块设备。在非 Linux 平台上，
前者会指向"另一个根"，后者干脆不存在；**脚本不崩，但数字静默失真** —— 这比报错更危险，因为它看起来正常。

修法（伪代码）：

```
采集「工作区所在分区」的容量（伪代码）
    锚点 ← 工作区路径所在分区的锚（Linux 是 /，Windows 是 C:\ 这类）
    用宿主语言标准库读取锚点的 可用 / 总 容量
    换算成人读单位，并给出已用百分比
    读不到 → 输出「探测不到（锚点不可用）」
    ※ 全程不调用平台专有命令

采集可移动 / 非系统设备（伪代码）
    若 平台 = Linux：调用块设备列表命令；命令不存在 ⇒ 视为「探不了」
    若 平台 = Windows：枚举盘符，跳过系统盘，逐个读容量
    其它平台：不猜
    「探不了」与「列表为空」是两个不同状态，必须分开返回
    由展示层把「探不了」写成一句自然语言说明
```

落地在 `scripts/state_snapshot.py`。因此 `STATE.md` 的机器段落在任何平台都"读得到、且不会静默失真"：
显示"本平台不自动探测"是**如实告知**，不是故障。

## 四、本机补做的验证（评审当时没能跑的那条链路）

- 铺开一个新工作区 → 体检 → 生成状态快照 → 建一次交流测试：**退出码全 0**；
- 新工作区体检唯一 ⚠️ 是"热记忆定位未填"，补上即全绿；
- 技能自身敏感串自检 ❌0；
- 三平台模拟：Linux 正常探测；macOS / Windows 的"探不了"路径输出自然语言说明，**不给错数**。

## 六、后续修订（v1.5.0，2026-10-02）

来源：**在一台真实机器的项目管理整顿之后**回填的 —— 那次踩到的不是"制度写得不够"，而是"制度没跟上实际形态"。

| 改了什么 | 为什么 |
| --- | --- |
| 项目区新增**两种形态**：`embedded` / `card`（一处真身 ＋ 登记卡，真身在工作区外） | 旧写法默认"项目就长在 `projects/` 里"，而实际用法是**工作区当控制台、项目真身在外盘**；旧"工作区干净镜像"机制因此必然漂移 |
| 体检新增 `cards` 项：核对**卡 ↔ 真身**（卡在不在、路径指不指得到、字段全不全、卡长不长、有没有漏登记的真身） | 卡制度最大的风险是"卡与真身对不上"，这是结构问题，机器能查 |
| **判断类的事（建不建、发不发、退不退役）写成自然语言建议**，不进脚本 | 判断没有唯一答案；写成硬校验只会逼人绕过它。判断归人，形式归脚本 |
| 隐私篇新增**可见性分级与推送闸门**（默认仅本机／默认 private／公开要人点头／按提交扫历史） | 旧文只讲"别把 Key 写进去"，没讲"什么时候可以外发" |
| `bootstrap.sh` 补 `--projects-mode` / `--truth-root`，并修正生成的 `[limits]`（原来把硬上限写成 150，与"150 触发、200 硬顶"的规则不一致） | 脚手架是**移民**第一课：铺出来的配置和规则不一致，后面所有工作区都跟着错 |

> 这一版也顺势把几个"只写在某台机器上"的经验（改名要动四处、已有远端仓库要接历史而不是另起）
> 提炼成**通用建议**，放进 [项目管理](项目管理.md)。

## 七、后续修订（v2.0.2，2026-10-14）

来源：**在一台真实机器上做"记忆系统迭代"时踩出来的** —— 这次的问题不是"制度写得不够"，而是**尺子与检查项缺了**：
规则只管住了"行数"，没管住"每会话真实成本"；文档里的路径**改名/搬家后没人发现**；内容外移后**分不清"丢了还是挪走了"**。

| 改了什么 | 为什么（实测证据） |
| --- | --- |
| 热文件加**字节尺**：`max_hot_bytes`（16 KB ⚠️）/ `hot_ceil_bytes`（20 KB ❌）/ `hot_budget_bytes`（注入预算 65,536 B） | 同样"70 行合规"，体积可以差 **5 倍**（0～59 KB）；行数只是排版尺，字节才是每会话付费的成本尺 |
| 体检新增 **`stale`** 项：失效的绝对/家目录路径，四档（未声明/已声明/基线/其他）＋**严区分级** | 真实工作区里一次扫出 **34 处失效路径**，其中 **4 处是活指针**（技能改名、库搬家、备份搬迁）—— 旧体检 15 项里没有任何一项能发现 |
| 新增 **`check_hard_values.py --externed`**：三类结论（真丢失／已外移／映射失效） | 压缩/清点后机械核对会报 **37 项"缺失"**，其实全是"外移到别处"；旧做法只能人工 grep 找真身 |
| 新增 **`closeout.sh`**：六步一键（台账→活窗口→失效扫描→状态表→**体检**→热区形态），失败即停 | "分步跑必漏步"：真实会话里改完热文件后 `STATE.md` 变旧，是**体检**抓到的 —— 顺序与自动化的价值就在这 |
| 热文件扩容口径：**早点扩**（S≥50% 且 W≤25% ⇒ 一次 +10 行；硬顶 90 行/20 KB） | 上限撞满时"能不能扩"原本靠人拍；现在有可算的形态信号（S 条目化率 / W 续行率）＋**字节硬顶兜底** |
| 记忆制度新增**第二轴：按取用延迟分层**（热/温/冷）＋三条判据 | 原"三层"按**变化速度**分（防漂移），缺**代价**这条正交轴：热区每会话付费，加一条前要先问"有没有一条该沉下去" |

> 一句话：v2.0.2 把"**尺子**（字节）、**体检**（失效路径）、**核对**（指针台账）、**流程**（一键收工）"补齐了；
> 判断仍归人，机器只负责**把看不见的漂移变成看得见的红灯**。

## 八、后续修订（v2.1.0，2026-10-20）

来源：**用户提出"记忆不能只记知识和经验，丧失了原始的感受记忆"** —— 这轮缺的不是检查项，而是
**整套制度没有"agent 自己"的位置**：三层按变化速度、八区按物的用途，日记无处可放。

| 改了什么 | 为什么 |
| --- | --- |
| 新增**智能体日记**（`memory/<日期>/智能体日记*.md`）：空白随日期目录创建、不强制写、不检查、不统计 | 给 agent 自己那侧的、跨会话连续的记忆一个位置；它是身份载体，不是效率功能 |
| 新增**豁免件**概念：显式配置 ＋ 按前缀窄口识别（`_common.is_diary` 单点实现） | 豁免若不显式，下一次体检就会把它当普通笔记压缩/删除；口子若不窄，就会变成绕过体检的后门 |
| 密钥/隐私扫描**不豁免** | 豁免的是"管理"，不是"安全"；红线不能因为一个豁免概念被稀释 |
| 文档写死"三不"：不表演、不为读者写、不进制度闭环 | 日记一旦被度量、被引用进规则，下一轮迭代就会把它优化成 KPI —— 真诚是唯一不能被优化掉的东西 |

## 九、后续修订（v2.1.1，2026-10-20）

来源：**用户要一个"每天回看过去"的机制** —— 但不是提醒、不是统计，而是"下一日期目录出现时，静默清掉更早的空白日记"。

| 改了什么 | 为什么 |
| --- | --- |
| `memory_query.py --rebuild`（收工第 1 步）静默清理：出现更晚日期目录后，删更早日期里**完全空白**的日记；最新一天保留、非空永不删、非日记文件不碰 | 空白日记是"当天没写"的合法状态，但留存久了会变成噪声；清理由脚本机械完成，**不占 agent 注意力、不产生提醒** |
| `[diary] cleanup_blank`（默认 true）可关 | 与其它豁免件一样：行为要显式、可关，才不会是暗箱 |
| 回归：新增 11 断言（清理/保留/单目录不触发/幂等/静默/开关） | 删文件是破坏性动作，必须钉住"只删完全空白"这条线 |

## 十、后续修订（v2.1.2，2026-10-20）

来源：**多会话同日时，模型"手动建空白日记"可能把已写内容覆盖掉**（本机实测出现过；把"创建"留在模型手里本身就是风险）。

| 改了什么 | 为什么 |
| --- | --- |
| `memory_query.py --rebuild` **静默自动创建**当天空白日记（当天目录已存在且目录里没有任何日记时；**独占创建**，已有/并发都安全失败、绝不覆盖） | 把"创建"从模型手里拿走 —— 模型不再需要、也不应该手动建空白；覆盖风险从根上消除 |
| 文档与热文件改成"**只追加或局部编辑，绝不整文件覆盖**" | 模型仍可写内容，但不再持有"覆盖"这个动作 |
| `[diary] auto_create`（默认 true）可关；回归新增 13 断言（创建/不覆盖/不重复建/无目录不建/开关/静默/与清理联动） | 与其它日记机制一样：显式、可关、有钉子 |

## 十一、后续修订（v2.2.0，2026-10-21）

来源：**用户指出热记忆"像法律又像百科"**、手册区有十几篇却没有"按事找"的表、长尾手册吃灰；而单篇压缩
让"新开笔记"比"合并维护"便宜，结论沉淀不下来。（用户自评：第二轮迭代压得太极端。）

| 改了什么 | 为什么 |
| --- | --- |
| **手册表**：`handbook/README.md` 按"我要做什么"列（场景→读哪篇→什么时候不用读），热文件只指向它 | 手册缺的不是检索，是**发现**：没有任务视图，长尾手册只能靠 `ls`；热文件于是被动兼任目录 |
| **主题卷宗**：`handbook/<主题>.md` 允许 `evolving`/`settled` 两态，可先进来再定型 | 给"有用但还没定型"的知识一个家；原来它只有两条路——碎在日期笔记里，或挤进热文件 |
| **归并优先于压缩**；阈值放宽（本机 200/120/280）；**不许为消 ⚠️ 只改状态** | 压缩只罚"维护"，新开文件几乎免费——激励反了；且"30 天 open"警告可被状态翻转消掉（实测做过） |
| 热文件重定为**行为守则**（本机 69→53 行 / 14.4→7.4 KB） | 守则＝还没识别出局面时就要生效的东西；可判定的交脚本、流程交手册；否则注入预算被百科吃掉 |

## 十二、后续修订（v2.2.1，2026-10-21）

来源：**"一天同类只落一篇"实际没做到**——同日同题会落好几篇，后面得轮着改；且限制太死会让"压缩后重写/再开一篇"更划算，总耗费反而更高。

| 改了什么 | 为什么 |
| --- | --- |
| 写入时机补"**一天一类只落一篇**：新建前看当天目录，同主题并入/追加，后续修改回原篇" | 碎片化的成本不在写，在**后面每次改都要轮着改**；在入口拦一下最便宜 |
| 压缩口径再放宽（本机 200/120/280 → 260/150/360），并写死"**归并优先于压缩、日志不硬压**" | 限制太死 → 达标的低成本动作只剩"新开一篇"或"压掉再重写"，反而更贵 |
