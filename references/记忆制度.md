# 记忆制度细则

## 一、区与判断标准（**默认六区，可加挂**）

| 区 | 放什么 | 判断标准 | 命名（用户口径） |
| --- | --- | --- | --- |
| `memory/` | 在办的事、试出的结论、失败尝试、原始输出、待办 | **要读**的叙述 | 按时间 `YYYY-MM-DD/主题.md` |
| `handbook/` | 已定型、实测通过、可照做的流程 / 结论 / 参数表 | **可照做**的速查 | 按主题 `<主题>.md` |
| `exchange/` | 出题 / 作答的受控交流 | **要传**的话 | 按时间 `YYYY-MM-DD-主题/` |
| `scratch/` | 可复跑的脚本、基准、产物（**没确认的复用产物先放这**） | **要跑**的东西 | 按种类 `<种类>/` |
| `projects/`〔加挂〕 | 要开发、会持续维护的项目：**内嵌真身**，或**真身在外、本区只放登记卡** | **要构建**的东西 | 按种类 `<项目>/` |
| `data/`〔加挂〕 | 机器用的大文件：活库、下载缓存、锁（可再生、不外发） | **机器用**的 | 按种类 `<种类>/` |
| `archive/` | 会被滚动窗口挤掉、不可再生的数据快照 | **要留**的数据 | `<种类>/<快照日期>/` |
| `trash/` | 用过且不会再读的产物 | **要扔**的东西 | 按种类 `<种类>/` |

**区清单是配置项**：`.memory-kit.toml` 的 `areas` 说了算（默认六区），不是硬编码 ——
`projects`、`data` 的模板随技能提供，`bootstrap.sh --areas ...` 可一并铺开。
**命名检查也从 `areas` 取区**，加挂区一样受"按种类"约束。加挂一个区要三样：
`templates/areas/<区>/README.md`、`areas` 里加一项、`AGENTS.md` 导航表补一行
（等该区**真的存在**再加链接，否则体检判断链）。

**先 `scratch/` 后 `projects/`**：新东西默认放 `scratch/`（可弃）；**用户确认**要长期维护才迁入并改掉所有引用。

**项目区的两种形态**（`.memory-kit.toml` 的 `[projects] mode`）：

- `embedded`（默认）：真身就在 `projects/<名>/`，工作区就是项目的家。
- `card`：**一处真身 ＋ 登记卡** —— 真身在工作区**外**的 `[projects] truth_root/<名>/`，
  本区只放一张 `projects/<名>/README.md`（默认 ≤40 行，**只放指针**：真身路径／类别／可见性／状态／git）。
  卡的模板在 `templates/projects/card.md`（`bootstrap.sh` 会铺成 `projects/_登记卡模板.md`）。

  **为什么**：同一份东西存多处会各自演化，最后"哪个算数"说不清（旧"工作区干净镜像"机制就死在这上面）。
  一处真身之后，**为了同步而同步的机制一律退役**。**判断类的事（建不建、发不发、退不退役）不写进脚本** ——
  见 [项目管理](项目管理.md)（自然语言的建议）；体检的 `cards` 项**只核对形式**。

**命名一句话**：记忆与交流按时间，其余一律按种类。同一种类的新批次**就地加文件或文件名带日期**，
不再新建日期目录。`memory/` 与 `archive/<种类>/` 是唯一的两种日期用法（前者是工作日记，后者是快照标识）。

## 二、三层内容分离（防漂移的核心机制）

| 层 | 文件 | 内容 | 谁写 | 行数 |
| --- | --- | --- | --- | --- |
| 热 | `AGENTS.md` | **只有**提示词、规则、长期习惯 + 一张"要什么去哪读"导航表 | 人 / AI | ≤ `max_hot_lines`（默认 70） |
| 半稳定 | `memory/settings.md` | 端点、Key 位置、路径、模型名、版本、口径坑 | 手改 | ≤ 150 |
| 易变 | `STATE.md` | 体积/行数、缓存、归档、磁盘、设备、白名单 | **脚本** | 不限，随时覆盖 |

漂移的三种典型病：同一句话抄在两个文件里（改一处忘另一处）、数字手写进热记忆、
"临时结论"长期留在 `memory/` 冒充定论。三种对应的药：**只写一次 + 链接指过来**、
**数字交脚本**、**定型就搬家**。

## 三、两条硬规则

1. **压缩两档**（`compress_trigger_lines` / `compress_target_lines` / `max_note_lines`）：
   `memory/` 与 `handbook/` 的单篇**到触发线（默认 150）就压缩，目标 80 行**；
   **实在压不到 80** 才退档：上限 +50（150 → 200）、下限 +40（80 → 120），即老实落在 **120~200 行**
   （别做半吊子压缩），末尾写明「压缩记录：删了什么、去哪了、为何到不了 80」。
   压缩顺序：① 删过程史（失败尝试留一句结论即可）；② 细节外移到脚本/手册。
   体检：过触发线判 ⚠️，超 `max_note_lines`（硬上限）判 ❌。
2. **结论前置**（`tldr_min_lines` / `tldr_head_lines`）：超过约 80 行的文档，
   开头 12 行内必须出现「结论 / 怎么做 / 坑」。体检判 ⚠️。

## 四、写入时机

- **别边做边写**：一件事没做完**不落盘**；一个阶段全部到位后**一次性**补/改 —— 改动要成块、频次低，
  比频繁小改更省事也更好读。
- 一次调查 / 调试 / 试验**结束时**落盘；同一类事情改同一个文件。
- 新增笔记后在 `memory/README.md` 索引表加一行（体检会查"没进索引"）。
- `AGENTS.md` 只在**规则或长期习惯变了**时改 —— 它不是日记。
- 定型（不再试验 + 实测通过 + 有出处）→ 搬进 `handbook/`，来源笔记压缩成指针。
- **项目要确认才建**：新东西先放 `scratch/`（可弃，先跑通功能小样）；**用户确认**要长期维护才升级成项目 ——
  走 [项目管理](项目管理.md) 的四步（真身＋README＋`git init`＋**当场定可见性**；`card` 形态再加一张登记卡），
  并改掉所有引用。
- **写完笔记跑三步**：`memory_query.py --rebuild`（台账跟上磁盘）→ `--refresh`（刷新各区 README 活窗口）→
  `memory_doctor.py`（体检）。**不再需要手动往 README 加索引行** —— 台账在 `index.json`（见第八节）。

## 五、体检各检查项

| 项（`--only` 名） | 查什么 | 级别 |
| --- | --- | --- |
| `config` | `.memory-kit.toml` 是否存在（缺了就用默认值） | ⚠️ |
| `links` | 所有 md 的相对链接是否解析得到 | ❌ |
| `placeholders` | 热记忆 `AGENTS.md` 里有没有没填的占位（`{{…}}` / `（待填…）`） | ⚠️ |
| `areas` | 六区 README 与 `memory/settings.md` 是否都在 | ❌ |
| `cards` | `[projects] mode = "card"` 时核对**卡 ↔ 真身**：卡在不在（❌）、真身路径指不指得到、必备字段全不全、卡超没超行数，以及真身根下有没有**没登记的项目**（⚠️） | ❌ / ⚠️ |
| `index` | 索引（JSON 台账）↔ 磁盘**双向一致**；README 是否引用 `settings.md` | ❌ |
| `aging` | 超 `note_stale_days` 仍 open 的笔记；正文总量 vs `budget_lines`（防"想记住一切"） | ⚠️ |
| `readmes` | 各区 README 是否超 `max_area_readme_lines`（防"台账塞 README"复发） | ⚠️ |
| `sizes` | `AGENTS.md` 超 `max_hot_lines`；单篇**过触发线**（⚠️）/ **超硬上限**（❌） | ⚠️ / ❌ |
| `tldr` | 超阈值文档有没有结论前置 | ⚠️ |
| `secrets` | 6 类凭据正则；豁免按基名匹配 | ❌ |
| `state` | `STATE.md` 是否比 `state.deps` 旧、或超 `state_max_age_days` | ⚠️ |
| `exchange` | 每个测试目录有 task/answer、状态合法、pending 是否超期 | ❌ / ⚠️ |
| `handbook` | 条目是否进索引；「最后验证」是否超 `handbook_max_age_days` | ❌ / ⚠️ |
| `naming` | 命名是否按"记忆交流按时间、其余按种类" | ❌ |

`--only a,b` 只跑其中几项；`--list` 列出全部。**❌ 必须清零，⚠️ 看情况**。

## 六、`.memory-kit.toml` 全字段

```toml
areas = ["memory", "handbook", "exchange", "scratch", "archive", "trash"]

[limits]
max_hot_lines = 70          # AGENTS.md 上限
max_note_lines = 200        # 单篇硬上限：超过判 ❌
compress_trigger_lines = 150 # 单篇过线判 ⚠️「该压缩」（0 = 不设触发线）
compress_target_lines = 80  # 压缩目标行数；退档 = 触发线+50（上限）/ 目标+40（下限）
tldr_min_lines = 80         # 超过就要有「结论」
tldr_head_lines = 12
state_max_age_days = 7
pending_max_age_days = 3    # 交流测试 pending 多久提醒
handbook_max_age_days = 90  # 「最后验证」多久提醒复审
max_area_readme_lines = 120 # 区 README 上限（只放规则 + 活窗口）
note_stale_days = 30        # memory 里 open 状态超这么久 → ⚠️「该结账了」

[secrets]
allow_files = []            # 允许出现敏感串的文件（按基名）；默认空 = 一律 ❌

[scan]
# 扫描范围：**默认不漫游整棵树**（大工作区/外来树的体检误报都出自漫游）
include = []                # 额外要递归扫的路径；"." = 退回整棵树
exclude = []                # 范围内整棵跳过（典型：工作区里放的外来树、技能/模板仓库检出）
secrets = "areas"           # 凭据层范围：areas（各区递归，默认，脚本也扫）| docs（同文档层）
max_file_bytes = 2097152    # 之上的文件不做文本检查（避免把大 dump 当文本读）

[projects]
mode = "embedded"           # embedded = 真身就在 projects/<名>/；card = 一处真身 ＋ 登记卡
truth_root = ""             # mode = "card" 时必填：真身根目录（工作区外的绝对路径）
card_max_lines = 40         # 登记卡行数上限（超了 → ⚠️：说明你在往卡里塞说明）
card_fields = ["真身", "可见性", "状态"]   # 卡里必须出现这几样（缺 → ⚠️）
audit_truth = true          # 反向核对"真身有、卡没有"（不想核对设 false）

[state]
collectors = []             # STATE.md 采集器 .py 路径（相对工作区或绝对）
deps = ["AGENTS.md"]        # 比 STATE.md 新 → 提示重生成
tools = []                  # 要打印版本的 CLI
```

没有这个文件也能跑（内置默认值），但会失掉项目差异 —— 体检会提醒。

## 七、常见漂移与对策

| 症状 | 对策 |
| --- | --- |
| 同一事实两处写法不一致 | 挑一处当唯一真源，另一处改成链接 |
| 热记忆越来越长 | 事实挪 `settings.md`、数字挪 `STATE.md`、流程挪 `handbook/` |
| 数字过期没人发现 | `state_snapshot.py --check` 挂进日常流程；体检查新鲜度 |
| 笔记越写越长 | 到触发线压到目标（150 → 80）；压不到才退档 120~200 并写明原因 |
| 结论无人复核就当真 | 走 `exchange/` 协议；复核说明验到哪一层 |
| 改了盘/库但文档没动 | 变动后立刻 `state_snapshot.py`，别攒 |
| **README 越写越长（台账膨胀）** | 台账搬进 `index.json`，README 只留规则 + 活窗口（`memory_query.py --refresh`）；体检 `readmes` 会把越线标出来 |
| **登记卡越写越长 / 真身搬了卡没改** | 卡只放指针，说明挪回真身 README；体检 `cards` 项按行数与真身路径提醒（判断类的事见 [项目管理](项目管理.md)） |
| **笔记只进不出、"想记住一切"** | `--stats` 看正文总量 vs `budget_lines`；`--stale` 找未结项；`--prune --before <日期> --apply` 批量 mv 进 `trash/`（`--delete` 单条） |

## 八、索引与散文分离（台账 ≠ 散文）

**一句话**：README 说规矩，JSON 记全部，程序做检索，正文永不删。

旧做法把**台账**（一行一条、O(条目数)）塞进 **README**（规则，O(1)）——两条规则因此结构性互斥：
"每篇必须进索引"（❌ 强制） + "单篇 ≤150/200 行"（❌ 强制） + 持续新增 ⇒ 无解。
实测：18 篇/天的强度下 `memory/README.md` **5 天撞 150 行、8 天撞 200 行**。

改法：

| 层 | 放哪 | 约束 |
| --- | --- | --- |
| **规则 + 活窗口** | 各区 `README.md` | 行数上限 `max_area_readme_lines`；活窗口由 `--refresh` 生成（memory = 近 `live_days` 天 + 未结项，≤ `live_rows` 行） |
| **全量台账（数据）** | `memory/index/YYYY-MM.json`、`<区>/index.json` | 不受 md 行数/断链规则约束；机器读 |
| **正文（散文）** | `memory/YYYY-MM-DD/主题.md` 等 | 照旧受 150 行压缩规则约束；**永不因索引而删** |

- **写入**：正文照旧写；写完跑 `--rebuild`（台账跟上）+ `--refresh`（活窗口）+ 体检 ——
  这两者**默认全区**（v1.3.1 起；只动一个区才加 `--zone <区名>`），别只重建 `memory` 让别区静默留旧。
- **阅读**：默认**按范围取**（`--since/--tag/--status/--grep/--stale`），不要全量翻 —— 这正是"防止过度阅读"。
- **结账**：`--stats` 看阅读面体量；`--prune`/`--delete` 把用不上的**移进 `trash/`**（`mv` 不 `rm`）并同步索引；
  "过去的全量记忆绝大多数用不上"≠ 要删光，而是**默认不读全部**。
- **`--rebuild` 是合并**：`desc/refs/remark/tags/status` 等人工字段一律继承（正文里显式声明的优先），
  所以重建不会把人工写的内容冲掉。
