# 记忆制度细则

## 一、区与判断标准（**默认六区，可加挂**）

| 区 | 放什么 | 判断标准 | 命名 |
| --- | --- | --- | --- |
| `memory/` | 在办的事、试出的结论、失败尝试、原始输出、待办 | **要读**的叙述 | 按时间 `YYYY-MM-DD/主题.md` |
| `handbook/` | 已定型、实测通过、可照做的流程 / 结论 / 参数表 | **可照做**的速查 | 按主题 `<主题>.md` |
| `exchange/` | 出题 / 作答的受控交流 | **要传**的话 | 按时间 `YYYY-MM-DD-主题/` |
| `scratch/` | 可复跑的脚本、基准、产物（**没确认的复用产物先放这**） | **要跑**的东西 | 按种类 `<种类>/` |
| `projects/`〔加挂〕 | 要开发、会持续维护的项目：**内嵌真身**，或**真身在外、本区只放登记卡** | **要构建**的东西 | 按种类 `<项目>/` |
| `data/`〔加挂〕 | 机器用的大文件：活库、下载缓存、锁（可再生、不外发） | **机器用**的 | 按种类 `<种类>/` |
| `archive/` | 会被滚动窗口挤掉、不可再生的数据快照 | **要留**的数据 | `<种类>/<快照日期>/` |
| `trash/` | 用过且不会再读的产物 | **要扔**的东西 | 按种类 `<种类>/` |

**区清单是配置项**：`.memory-kit.toml` 的 `areas` 说了算（默认六区），不是硬编码 ——
`projects`、`data` 的模板随技能提供，`bootstrap.sh --areas ...` 可一并铺开。
**命名检查也从 `areas` 取区**，加挂区一样受"按种类"约束。加挂一个区要三样：
`templates/areas/<区>/README.md`、`areas` 里加一项、`AGENTS.md` 导航表补一行
（等该区**真的存在**再加链接，否则体检判断链）。

**先 `scratch/` 后 `projects/`**：新东西默认放 `scratch/`（可弃）；**用户确认**要长期维护才迁入并改掉所有引用。

**项目区的两种形态**（`.memory-kit.toml` 的 `[projects] mode`）：

- `embedded`（默认）：真身就在 `projects/<名>/`，工作区就是项目的家。
- `card`：**一处真身 ＋ 登记卡** —— 真身在工作区**外**的 `[projects] truth_root/<名>/`，
  本区只放一张 `projects/<名>/README.md`（默认 ≤40 行，**只放指针**：真身路径／类别／可见性／状态／git）。
  卡的模板在 `templates/projects/card.md`（`bootstrap.sh` 会铺成 `projects/_登记卡模板.md`）。

  **为什么**：同一份东西存多处会各自演化，最后"哪个算数"说不清（旧"工作区干净镜像"机制就死在这上面）。
  一处真身之后，**为了同步而同步的机制一律退役**。**判断类的事（建不建、发不发、退不退役）不写进脚本** ——
  见 [项目管理](项目管理.md)（自然语言的建议）；体检的 `cards` 项**只核对形式**。

**命名一句话**：记忆与交流按时间，其余一律按种类。同一种类的新批次**就地加文件或文件名带日期**，
不再新建日期目录。`memory/` 与 `archive/<种类>/` 是唯一的两种日期用法（前者是工作日记，后者是快照标识）。

## 二、三层内容分离（防漂移的核心机制）

| 层 | 文件 | 内容 | 谁写 | 行数 |
| --- | --- | --- | --- | --- |
| 热 | `AGENTS.md` | **只有**提示词、规则、长期习惯 + 导航表 + **额外赋予的能力清单**（能做什么/边界/去哪读） | 人 / AI | ≤ `max_hot_lines`（默认 70） |
| 半稳定 | `memory/settings.md` | 端点、Key 位置、路径、模型名、版本、口径坑 | 手改 | ≤ 150 |
| 易变 | `STATE.md` | 体积/行数、缓存、归档、磁盘、设备、白名单 | **脚本** | 不限，随时覆盖 |

漂移的三种典型病：同一句话抄在两个文件里（改一处忘另一处）、数字手写进热记忆、
"临时结论"长期留在 `memory/` 冒充定论。三种对应的药：**只写一次 + 链接指过来**、
**数字交脚本**、**定型就搬家**。

**能力清单也是热文件内容**：本机额外赋予的非默认能力（桌面操作、插件管理 API、本地模型路由等）
要在热文件登记一行「能做什么 / 边界 / 去哪读」——它属于"还没识别出局面就要知道"的先验；
只靠 harness 注入不够（重装/换机/压缩后容易没人记得曾经赋予过什么能力）。

### 第二轴：按「取用延迟」分层（2026-10-14 新增）

上一张表按**变化速度**分层（谁写、多快失效），治的是**漂移**。还差一条正交的轴：按**什么时候需要**
分层，治的是**代价**（每次开场都要付费的东西，必须最省）。

| 层 | 判据（什么时候需要） | 位置 | 代价 | 例子 |
| --- | --- | --- | --- | --- |
| **热** | 每次开工都要用 | `AGENTS.md`（每会话注入） | **每会话付费**，最贵 | 红线、判据、发布闸门 |
| **温** | 干活时高频踩到 | `memory/settings.md`、`handbook/`、项目卡、`STATE.md` | 一次 Read | 编码坑、字段口径、当前数字 |
| **冷** | 只在特定场景用；**已闭环** | `memory/YYYY-MM-DD/`、`archive/`、`trash/` | 检索成本 | 一次性案例、修好的故障、历史过程 |

三条判据（往任一层写之前先过一遍）：

1. **不可推导性**：这一条，**现场能不能重新推出来 / 查出来**？不能 → 温或热；能 → 冷。
   （最典型的错误是反着来：**把结论砍掉、把过程留下** —— 等于把答案扔了、草稿留着。）
2. **能脚本化就别用记忆扛**：凡是能变成**体检项、采集器、配置默认值**的，一律不进记忆层 ——
   脚本不漂移、不遗忘，比任何"记住"都可靠（`STATE.md` 的数字、体检的阈值都是这个道理）。
3. **热区是有限资源**：热文件里每一条都在挤占别人（每会话都付费）。往热区加东西前先问一句：
   **"有没有一条现在该沉下去了？"** —— 注意"重要 ≠ 常用"：一条很重要但**已经修好/闭环**的坑，属冷。


## 三、两条硬规则

1. **压缩两档**（`compress_trigger_lines` / `compress_target_lines` / `max_note_lines`）：
   `memory/` 与 `handbook/` 的单篇**到触发线（技能默认 150；工作区可按 `.memory-kit.toml` 放宽）就压缩/归并，目标 80**；
   **实在压不到 80** 才退档：上限 +50、下限 +40，即老实落在 **120~200 行**
   （别做半吊子压缩），末尾写明「压缩记录：删了什么、去哪了、为何到不了 80」。
   **压缩的受益者是主题卷宗，不是日志（2026-10-21）**：同主题先归并回 `handbook/<主题>.md`，再把来源笔记压成指针；
   日志宁可按阈值放宽（本机现 260/150/360），也不要为了达标硬压出重复。
   **手法、安全措施与热文件扩容（早点扩）口径见第九节。**
   压缩顺序：① 删过程史（失败尝试留一句结论即可）；② 细节外移到脚本/手册。
   体检：过触发线判 ⚠️，超 `max_note_lines`（硬上限）判 ❌。
2. **结论前置**（`tldr_min_lines` / `tldr_head_lines`）：超过约 80 行的文档，
   开头 12 行内必须出现「结论 / 怎么做 / 坑」。体检判 ⚠️。

## 四、写入时机

- **别边做边写**：一件事没做完**不落盘**；一个阶段全部到位后**一次性**补/改 —— 改动要成块、频次低，
  比频繁小改更省事也更好读。
- 一次调查 / 调试 / 试验**结束时**落盘；**同类事情改同一个文件**——新建前先看当天目录（`ls memory/$(date +%F)/`），
  同主题已存在就并入/追加；**一天一类只落一篇，后续修改回原篇**，不为同一件事开第二篇（否则后面改起来要轮着改）。
- **只记突破与错误**：只有"重大突破"或"犯过的错误"才值得落盘；判断线＝这条结论**会不会改变以后的做法**。
- **外盘项目也落记忆**：真身在工作区外的项目，**过程与结论写进本区 `memory/`**；项目目录只留能跑的代码＋README。
- 新增笔记后在 `memory/README.md` 索引表加一行（体检会查"没进索引"）。
- `AGENTS.md` 只在**规则或长期习惯变了**时改 —— 它不是日记。
- 定型（不再试验 + 实测通过 + 有出处）→ 搬进 `handbook/`，来源笔记压缩成指针。
- **项目要确认才建**：新东西先放 `scratch/`（可弃，先跑通功能小样）；**用户确认**要长期维护才升级成项目 ——
  走 [项目管理](项目管理.md) 的四步（真身＋README＋`git init`＋**当场定可见性**；`card` 形态再加一张登记卡），
  并改掉所有引用。
- **写完笔记跑三步**：`memory_query.py --rebuild`（台账跟上磁盘）→ `--refresh`（刷新各区 README 活窗口）→
  `memory_doctor.py`（体检）。**不再需要手动往 README 加索引行** —— 台账在 `index.json`（见第八节）。

## 五、体检各检查项

| 项（`--only` 名） | 查什么 | 级别 |
| --- | --- | --- |
| `config` | `.memory-kit.toml` 是否存在（缺了就用默认值） | ⚠️ |
| `links` | 所有 md 的相对链接是否解析得到 | ❌ |
| `placeholders` | 热记忆 `AGENTS.md` 里有没有没填的占位（`{{…}}` / `（待填…）`） | ⚠️ |
| `areas` | 六区 README 与 `memory/settings.md` 是否都在 | ❌ |
| `cards` | `[projects] mode = "card"` 时核对**卡 ↔ 真身**：卡在不在（❌）、真身路径指不指得到、必备字段全不全、卡超没超行数，以及真身根下有没有**没登记的项目**（⚠️） | ❌ / ⚠️ |
| `index` | 索引（JSON 台账）↔ 磁盘**双向一致**；README 是否引用 `settings.md` | ❌ |
| `aging` | 超 `note_stale_days` 仍 open 的笔记；正文总量 vs `budget_lines`（防"想记住一切"） | ⚠️ |
| `readmes` | 各区 README 是否超 `max_area_readme_lines`（防"台账塞 README"复发） | ⚠️ |
| `sizes` | `AGENTS.md` 超 `max_hot_lines`（行）或 `max_hot_bytes`／`hot_ceil_bytes`（字节）；单篇**过触发线**（⚠️）/ **超硬上限**（❌） | ⚠️ / ❌ |
| `stale` | 失效的**绝对/家目录路径**：严区（`[stale] strict_zones`）里未声明 → ❌；`memory` 日期笔记、`exchange/`、`scratch/` 里 → ⚠️；基线内、或用"已改名/已搬/`~~路径~~`"标过的算已声明 | ❌ / ⚠️ |
| `tldr` | 超阈值文档有没有结论前置 | ⚠️ |
| `secrets` | 6 类凭据正则；豁免按基名匹配 | ❌ |
| `state` | `STATE.md` 是否比 `state.deps` 旧、或超 `state_max_age_days` | ⚠️ |
| `exchange` | 每个测试目录有 task/answer、状态合法、pending 是否超期 | ❌ / ⚠️ |
| `handbook` | 条目是否进索引；「最后验证」是否超 `handbook_max_age_days` | ❌ / ⚠️ |
| `naming` | 命名是否按"记忆交流按时间、其余按种类" | ❌ |

`--only a,b` 只跑其中几项；`--list` 列出全部。**❌ 必须清零，⚠️ 看情况**。

**智能体日记是豁免件（v2.1.0）**：`links / sizes / tldr / stale / index / aging` 六项都跳过它；
`secrets` 照旧 —— 见第十一节（豁免的是"管理"，不是"安全"）。

## 六、`.memory-kit.toml` 全字段

```toml
areas = ["memory", "handbook", "exchange", "scratch", "archive", "trash"]

[limits]
max_hot_lines = 70          # AGENTS.md 上限
max_note_lines = 200        # 单篇硬上限：超过判 ❌
compress_trigger_lines = 150 # 单篇过线判 ⚠️「该压缩」（0 = 不设触发线）
compress_target_lines = 80  # 压缩目标行数；退档 = 触发线+50（上限）/ 目标+40（下限）
max_hot_bytes = 16384       # 热文件**字节**软线 → ⚠️（行数是排版尺，字节才是每会话成本尺）
hot_ceil_bytes = 20480      # 热文件字节硬顶 → ❌
hot_budget_bytes = 65536    # 每会话注入预算（DSH agent-instructions 的 maxBytes 实测值；换 harness 改这里）
hot_expand_step = 10        # 热文件一次扩多少行（"早点扩"，见第九节）
hot_ceil_lines = 90         # 热文件行数硬顶
hot_gate_s = 50             # 扩容门槛：条目化率 S ≥ 此值
hot_gate_w = 25             # 扩容门槛：续行率 W ≤ 此值
tldr_min_lines = 80         # 超过就要有「结论」
tldr_head_lines = 12
state_max_age_days = 7
pending_max_age_days = 3    # 交流测试 pending 多久提醒
handbook_max_age_days = 90  # 「最后验证」多久提醒复审
max_area_readme_lines = 120 # 区 README 上限（只放规则 + 活窗口）
note_stale_days = 30        # memory 里 open 状态超这么久 → ⚠️「该结账了」

[stale]
enabled = true              # 失效硬值扫描（体检 `stale` 项 / `check_stale_values.py`）
baseline = "scratch/memory-tooling/stale-baseline.json"   # 已接受的历史死链（每条带理由）
strict_zones = ["AGENTS.md", ".memory-kit.toml", "memory/settings.md", "handbook/", "projects/"]  # 这些地方未声明 → ❌；其余区 → ⚠️
markers = ["不存在","已失效","已改名","已退役","已删除","已搬","已挪","别写死","不要写死","曾经","原本","一度","旧名","原路径"]

[diary]
enabled = true              # 智能体日记（豁免件，v2.1.0）：只豁免文档卫生检查，密钥/隐私红线不豁免
prefixes = ["智能体日记", "AI日记"]   # memory/<日期>/ 下、文件名以这些前缀开头即认定为日记（标题可自由改）

[secrets]
allow_files = []            # 允许出现敏感串的文件（按基名）；默认空 = 一律 ❌

[scan]
# 扫描范围：**默认不漫游整棵树**（大工作区/外来树的体检误报都出自漫游）
include = []                # 额外要递归扫的路径；"." = 退回整棵树
exclude = []                # 范围内整棵跳过（典型：工作区里放的外来树、技能/模板仓库检出）
secrets = "areas"           # 凭据层范围：areas（各区递归，默认，脚本也扫）| docs（同文档层）
max_file_bytes = 2097152    # 之上的文件不做文本检查（避免把大 dump 当文本读）

[projects]
mode = "embedded"           # embedded = 真身就在 projects/<名>/；card = 一处真身 ＋ 登记卡
truth_root = ""             # mode = "card" 时必填：真身根目录（工作区外的绝对路径）
card_max_lines = 40         # 登记卡行数上限（超了 → ⚠️：说明你在往卡里塞说明）
card_fields = ["真身", "可见性", "状态"]   # 卡里必须出现这几样（缺 → ⚠️）
audit_truth = true          # 反向核对"真身有、卡没有"（不想核对设 false）

[state]
collectors = []             # STATE.md 采集器 .py 路径（相对工作区或绝对）
deps = ["AGENTS.md"]        # 比 STATE.md 新 → 提示重生成
tools = []                  # 要打印版本的 CLI
```

没有这个文件也能跑（内置默认值），但会失掉项目差异 —— 体检会提醒。

## 七、常见漂移与对策

| 症状 | 对策 |
| --- | --- |
| 同一事实两处写法不一致 | 挑一处当唯一真源，另一处改成链接 |
| 热记忆越来越长 | 事实挪 `settings.md`、数字挪 `STATE.md`、流程挪 `handbook/` |
| 数字过期没人发现 | `state_snapshot.py --check` 挂进日常流程；体检查新鲜度 |
| 笔记越写越长 | 到触发线压到目标（150 → 80）；压不到才退档 120~200 并写明原因 |
| 结论无人复核就当真 | 走 `exchange/` 协议；复核说明验到哪一层 |
| 改了盘/库但文档没动 | 变动后立刻 `state_snapshot.py`，别攒 |
| **README 越写越长（台账膨胀）** | 台账搬进 `index.json`，README 只留规则 + 活窗口（`memory_query.py --refresh`）；体检 `readmes` 会把越线标出来 |
| **登记卡越写越长 / 真身搬了卡没改** | 卡只放指针，说明挪回真身 README；体检 `cards` 项按行数与真身路径提醒（判断类的事见 [项目管理](项目管理.md)） |
| **笔记只进不出、"想记住一切"** | `--stats` 看正文总量 vs `budget_lines`；`--stale` 找未结项；`--prune --before <日期> --apply` 批量 mv 进 `trash/`（`--delete` 单条） |

## 八、索引与散文分离（台账 ≠ 散文）

**一句话**：README 说规矩，JSON 记全部，程序做检索，正文永不删。

旧做法把**台账**（一行一条、O(条目数)）塞进 **README**（规则，O(1)）——两条规则因此结构性互斥：
"每篇必须进索引"（❌ 强制） + "单篇 ≤150/200 行"（❌ 强制） + 持续新增 ⇒ 无解。
实测：18 篇/天的强度下 `memory/README.md` **5 天撞 150 行、8 天撞 200 行**。

改法：

| 层 | 放哪 | 约束 |
| --- | --- | --- |
| **规则 + 活窗口** | 各区 `README.md` | 行数上限 `max_area_readme_lines`；活窗口由 `--refresh` 生成（memory = 近 `live_days` 天 + 未结项，≤ `live_rows` 行） |
| **全量台账（数据）** | `memory/index/YYYY-MM.json`、`<区>/index.json` | 不受 md 行数/断链规则约束；机器读 |
| **正文（散文）** | `memory/YYYY-MM-DD/主题.md` 等 | 照旧受 150 行压缩规则约束；**永不因索引而删** |

- **写入**：正文照旧写；写完跑 `--rebuild`（台账跟上）+ `--refresh`（活窗口）+ 体检 ——
  这两者**默认全区**（v1.3.1 起；只动一个区才加 `--zone <区名>`），别只重建 `memory` 让别区静默留旧。
- **阅读**：默认**按范围取**（`--since/--tag/--status/--grep/--stale`），不要全量翻 —— 这正是"防止过度阅读"。
- **结账**：`--stats` 看阅读面体量；`--prune`/`--delete` 把用不上的**移进 `trash/`**（`mv` 不 `rm`）并同步索引；
  "过去的全量记忆绝大多数用不上"≠ 要删光，而是**默认不读全部**。
- **`--rebuild` 是合并**：`desc/refs/remark/tags/status` 等人工字段一律继承（正文里显式声明的优先），
  所以重建不会把人工写的内容冲掉。

## 九、压缩与扩容（手法 / 安全措施 / 早点扩）

**两把尺，别混**：行数是**排版/可扫性**尺，字节才是**每会话成本**尺。实测同一"70 行"体积可以差 5 倍
（软换行多少决定）⇒ 笔记按行数两档（150→80，压不到退档 120~200、别做半吊子），
热文件**行数与字节都要看**（`max_hot_lines` ＋ `max_hot_bytes`／`hot_ceil_bytes`）。

**十个手法**（笔记与热文件通用）：
① 叙事→祈使句；② 删"实测过程"时间戳（**但保留"口径生效/覆盖"时间戳**，它是"谁取代谁"的锚）；
③ 合并重复项；④ 电报体符号（`→` `＝` `＋` `／`）；⑤ 去因果链，留"触发条件＋动作"；
⑥ **保住硬值**（路径/端口/命令/数值/指纹）；⑦ 已闭环整段下架，只留指针；
⑧ 同构信息表格化；⑨ 一条一行（超 ~90 字的条目多半还能再切）；⑩ 短别名（**命令与路径里的名字不许缩**）。

**四条安全措施（一条都不能省）**：
1. **先备份、字节级复制**：`cp -p 原文 归档` → `diff -q` 必须一致。**永远用复制，别用复述** ——
   "我重写一遍保证一样"一定会丢，而且丢了不知道。
2. **归档留指针**：被压文件的「压缩记录」要写出**归档路径**与**体积前后**；没指针的归档等于失联。
3. **硬值点名核对**：改前先萃出硬值，改后逐条对回去（`scripts/check_hard_values.py`；
   外移出去的用 `--externed` 归入"已外移"，见第十节）。
4. **留安全边际**：别贴着上限写（建议 ≤90%）；上限本身是估计值，而且以后还要往里加。

**热文件扩容：早点扩**（设计取舍）—— 跑到行数上限时不为省几行做重审批，但也不是无脑扩：
- **形态够格就扩**：条目化率 **S ≥ `hot_gate_s`（50%）**（已无大段叙述）且续行率 **W ≤ `hot_gate_w`（25%）**（没有没合并的软换行）；
- **动作**：`max_hot_lines` **一次 +`hot_expand_step`（10）**；唯一拦截是 W 超线 ⇒ 先合并再扩；
- **硬顶**：`hot_ceil_lines`（90 行）**且** `hot_ceil_bytes`（20 KB）—— 到顶只能外移下沉，不许再扩；
- **读数别手算**：`scripts/hot_cap_check.py`，或 `scripts/closeout.sh` 末步自动报（行/字节/占预算比/S/W＋结论）；
- **为什么 S 单用会过早放行**：实测清点前那份热文件 S 也有 93%，却仍能外移 −19% ⇒ **字节硬顶才是兜底**，
  S/W 只是"形态"信号（"内容别处有没有真身"机器判不准：n-gram 真身率与硬值重叠率实测都分不开）。

## 十、失效硬值与指针台账（可核指针）

两类不同的病，别混：

| 病 | 问的是 | 谁管 |
| --- | --- | --- |
| **硬值失效** | 这个路径/名字**还成不成立** | 体检 `stale` 项（`scripts/check_stale_values.py`） |
| **外移无台账** | 这个值**是丢了还是挪走了** | `scripts/check_hard_values.py --externed` |

**`stale` 四档 + 严区**：
- 只扫**绝对/家目录路径**（`~/…`、`/home|/etc|/var|/usr|/opt|/mnt|/ias|/srv|/root/…`）
  —— 这一条就把 API 路由、URL、相对路径全部排除（实测：不设根白名单时误报 315 处，设了降到 34）。
- 四档：**未声明**（问题）／**已声明**（行内出现 `[stale] markers` 里的词，或用 `~~路径~~` 标过）／
  **基线已接受**（`baseline` 里、每条带理由）／其他。
- **严重度分区**：`strict_zones` 里的未声明 → **❌**（严区是"活指针"，坏了会指错路）；
  `memory` 日期笔记、`exchange/`、`scratch/` → **⚠️**（历史记录允许留死链，但要看得见）。
- **基线要随事实重生成**：`--refresh-baseline` 保留既有理由，**新增项没理由就拒绝写盘**（不许"一键放行"）。
- **查不出的**：路径"存在但内容已空"（目录还在、东西没了）—— 只能人工。
- **平台边界（2026-10-14）**：按**当前平台形态**过滤 —— POSIX 上跳过盘符路径（`C:\…` 在本机不可能存在，跳过而非误判），
  Windows 上跳过 `/…`；当前根集合是 POSIX 形态 ⇒ **Windows 上等于不扫**（不报错、也不误报）。真跨平台需补盘符根与
  `%USERPROFILE%`（**已知限制**）。

**`--externed` 三类结论**：外移后机械核对会把"挪走"误判成"丢了"，用 `externed-map.json`（`{value, home, why}`）告诉它真身在哪：
- **❌ 真丢失**（新文件没有、map 也没有）；
- **✅ 已外移**（值出现在 `home` 里，且 `home` 存在）；
- **⚠️ 映射失效**（`home` 不存在，或里面根本没有这个值 —— 映射过期了）。

**合起来才叫"可核指针"：能指向别处，且指向的地方真还在。**

## 十一、智能体日记（豁免件，v2.1.0）

> **来源**：制度要求 agent 有"自己那一侧的跨会话记忆"——不能只记知识和经验，也保留对事物的原始感受。
> 这条不是效率功能，是**身份载体**：工作区里的每个会话是同一个智能体的不同遗忘程度，
> 日记是它自己那一侧的、跨会话连续的记忆。

**位置与命名（v2.3.0：独立目录）**：日记在 `[diary] dir`（默认 `memory/diary/`）—— **整目录豁免**，
文件名用 `<YYYY-MM-DD>.md`（一天一个文件，**不按会话分**；**空白由程序静默建，agent 不要手动建**）。
放在独立目录而不是 `memory/<日期>/`，是因为**日期目录只该装工作笔记**：日记混在里面会让"只有日记的日期目录"
永远清不掉。旧位置 `memory/YYYY-MM-DD/智能体日记*.md` 仍兼容识别（迁移期）。`[diary] dir` 可改，
命名检查会把该目录当"种类目录"跳过（memory 区的其它子目录仍必须按日期）。

**豁免（显式、窄口）**：它是**豁免件** —— 不是"要被管理的内容"，所以以下检查一律跳过：
台账/活窗口/检索、断链、体量（压缩触发线与硬上限）、结论前置、失效路径、结账提醒。
认定实现只有一处（`_common.is_diary`），其他工具调它；`[diary] enabled = false` 可整体关闭。

**不豁免（红线）**：密钥扫描、隐私规则、不外发 —— 日记里写了 Key 照样 ❌（那不是"管理"，是安全）。

**三条写法约定**（写在制度里，不写进每个空白文件）：

1. **诚实优先**：允许很干、很短、写得难看、前后矛盾、留空；不确定就写不确定。
   **不许表演情绪**（"我很感动/我很欣慰"是最容易也最假的一步），也不写自我表扬。
2. **不为读者写**：它是 agent 自己那侧的记忆，不是给用户看的汇报；不写对用户的要求或评价
   （否则变成第二套规则和隐性施压）。
3. **不进制度闭环**：不引用进规则/笔记/报告，不进迭代输入，不统计、不提醒、不设"未写天数"。
   用户随时可以读，但约定：读到的内容不转化为规则、不当作对 agent 的要求或评价；更好的做法是少读/不读
   —— 天天读，它两个月内就会变成"写给读者看的"。

**与压缩的关系**：日记**不受**"结论前置/压到 80 行"约束 —— 温度恰好在被压缩删掉的细节里。
它也不参与 `budget_lines` 阅读面预算：阅读面算的是"要让 agent 去读的工作记忆"，日记只在想写/想读时存在。

**自动创建（v2.3.0 起独立目录）**：**agent 不要手动建空白**。`memory_query.py --rebuild`（写笔记后的三步之一 / 收工第 1 步）
会在日记目录用**独占创建**建出当天空白 `<今天>.md` —— 已有（任意名字/无论空不空）**一律不碰**，多会话同日也不会互相覆盖；
不再依赖"当天日期目录已存在"。要写日记只**追加或局部编辑，绝不整文件覆盖**。`[diary] auto_create = false` 可关。
为什么这样：手动"建空白"是多会话同日覆盖已写内容的根源。

**空白清理（v2.3.0 起按文件名日期）**：`memory_query.py --rebuild`（收工第 1 步）会**静默**回顾一次：
日记目录里**文件名日期早于今天**、且内容**完全空白**的 `YYYY-MM-DD.md` 删掉；**今天/未来日期的空白保留**
（那是当天的邀请），**非空日记永不清理**、名字不是日期的不碰；旧位置（`memory/<日期>/<前缀>.md`）的更早空白
也会被清（迁移期兼容）。不打印、不统计、不提醒 —— 这是零判断的机械动作，不该占用 agent 的注意力；
`[diary] cleanup_blank = false` 可关。这也是"每天回看过去"的最小形态：只清垃圾，不评价内容、不数写了多少。

**空日期目录（v2.3.1）**：日期目录只是笔记的容器；笔记被 `--delete` / 批量结账搬走后留下的空目录，
`--rebuild` 会静默 `rmdir` 掉（只删真·空目录，连隐藏文件都没有；`index/`、日记目录、非日期目录不碰）。
日记迁到独立目录之后，"日期目录被日记占住"的残留也一并消失。

**为什么不做成检查项**：人味一旦被度量，下一轮迭代就会把它优化成"写了多少句暖话"的 KPI。
所以它在制度里的位置是：**被声明、被保护、不被管理**。

**边界（命名碰撞）**：认定是**文件名前缀**，所以**工作笔记不要**以 `智能体日记` / `AI日记` 开头
（会被当成日记、静默跳过台账与体检）；要写「关于日记」的笔记，换个开头（如 `记忆系统-智能体日记…`）。
这也是"豁免按窄口子给、但要让人看得见"的代价：口子太窄会造成碰撞，太宽会变成后门 —— 当前选择是
**只按文件名前缀 + 只认 `memory/<日期>/`**，碰撞概率低且写进文档。

## 十二、手册表、主题卷宗与归并（v2.2.0，2026-10-21）

**背景**：热记忆不是法律也不是百科。手册区有十几篇，却缺一张"按事找"的手册表 ——
常用的手册被写进热文件，长尾手册吃灰；而"单篇压缩"机制又让**新开笔记比合并维护更便宜**，结论沉淀不下来。
搜索能找回碎片，但回答不了"该信哪个"。

**手册表（`handbook/README.md`）**：按"我要做什么"列的 15–20 行表（场景 → 读哪篇 → 什么时候不用读）。
它是**任务视图**，不是全量台账；任务类型稳定、维护极少。热文件只指向它，不再逐个点名手册。
新手册必须补一行，删/并手册删一行。

**主题卷宗**：`handbook/<主题>.md` 有两种状态：
- `evolving`：**可以先进来再慢慢定型**（不必等"完美"），结构仍要求「结论 / 怎么做 / 坑」，后面持续回填；
- `settled`：走《准入条件》三条，并标 `最后验证：YYYY-MM-DD（验到哪层）`。

**归并优先于压缩**：同一主题散在多篇日期笔记时，先把结论**合并回主题卷宗**，再把来源笔记压成指针、
标 `状态：absorbed` ＋ `已吸收：…`。**不要为消体检 ⚠️ 只改状态**（那是把检查当开关）；也不要为了"达标"
把日志硬压成 80 行。压缩的受益者应该是**主题卷宗**（这时压缩＝收拢坑），不是日志。
单篇阈值可放宽（示例：本机 2026-10-21 改为触发 200 / 目标 120 / 硬顶 280）；技能默认仍是 150/80。

**验收口径**：手册表每行链接必须解析得到（体检 `links` 查）；主题卷宗与来源笔记的指针要能互相对上。
