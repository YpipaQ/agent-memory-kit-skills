# 工具与脚本

所有脚本**零第三方依赖**（纯标准库）：有 `tomllib`（Python ≥ 3.11）就用它，没有就用内置的**极简 TOML 子集**解析
⇒ **Python ≥ 3.8 可用**。默认也不调用任何外部 CLI（只有你显式登记的采集器/工具版本探测才会去调）。
工作区里的 `scratch/memory-tooling/*` 是**薄壳**，实现只有这一份 —— 改逻辑改这里。

## 一、根定位（所有脚本一致）

优先级：`--root <路径>` → 环境变量 `MEM_KIT_ROOT` → 从当前目录向上找 `.memory-kit.toml`
→ 向上找同时有 `AGENTS.md` 与 `memory/` 的目录 → 当前目录。
薄壳脚本会自动补上 `--root <工作区>`，所以在任何目录下调用都指向正确的工作区。

## 二、`memory_doctor.py`

```bash
python3 scripts/memory_doctor.py --root <工作区> [--only links,secrets] [--list]
```

- 退出码：`0` 无 ❌ / `1` 有 ❌ / `2` 用法错。
- 检查项名单见 [`记忆制度.md`](记忆制度.md) 第五节；`--list` 现查。
- 阈值与豁免全在 `.memory-kit.toml`，脚本里没有项目特定值。
- 输出是**给人和 AI 都看的**：每项一行 ✅/⚠️/❌，末尾一行小结。

## 三、`state_snapshot.py`

```bash
python3 scripts/state_snapshot.py --root <工作区>          # 写入 <工作区>/STATE.md
python3 scripts/state_snapshot.py --root <工作区> --print  # 只看不写
python3 scripts/state_snapshot.py --root <工作区> --check  # 退出码 1 = 该重生成
```

内置段落：归档目录体积与文件数、**工作区所在分区**的可用空间、USB/可移动设备、工具版本。
项目段落由**采集器**产生，顺序按配置里 `collectors` 的书写顺序插在标题之后。

**跨平台约定（重要）**：内置段落**不依赖任何平台专有命令** —— 分区容量走宿主语言的标准库；
可移动设备按平台探测，**探不到就写一句自然语言说明，绝不填一个"看着正常、其实是错的"数字**
（例如按 Linux 习惯去列分子区容量，在 Windows/Git Bash 下会指向另一个"根"，且脚本不报错）。
所以 `STATE.md` 在任何平台都"读得到、且不会静默失真"；某段显示"本平台不自动探测"是**如实告知**，不是故障。

## 四、采集器写法

```python
# <工作区>/scratch/memory-tooling/collectors/xxx.py
from pathlib import Path

def collect(root: Path, cfg: dict) -> list[str]:
    """返回 markdown 行（含自己的 `## 标题`）。"""
    return ["## 某数据", "", "| 项 | 值 |", "| --- | --- |", "| 行数 | 123 |"]
```

- 采集器**只读**，不改被采集的东西；失败不影响生成（STATE.md 里会显示一行错误）。
- 有副作用的探测要挡住：例如"某命令会在库不存在时创建空壳"，就先判断文件在不在。
- 随技能提供两个预设：`hithink_market_db.py`（本地 DuckDB 行情库 + 下载缓存）、
  `dsh_routes.py`（DSH 模型路由与 subagent 白名单）。`bootstrap.sh --preset hithink` 会带上前者。

## 五、`new_exchange.sh`

```bash
bash scripts/new_exchange.sh --root <工作区> "YYYY-MM-DD-主题" "一句话说明"
ISSUER=teammate-x bash scripts/new_exchange.sh --root <工作区> "..." "..."
```

建目录 → 用模板生成 `task.md`（替换 `{{主题}}` `<主题>` 两种占位、出题方、出题时间）→ 拷**空的** `answer.md`
→ 打印"出题方写什么、作答方只能写什么"的提示。
退出码：`0` 成功 / `2` 目录已存在 / `3` 模板缺失（会回退到技能自带模板）/ `4` 目录名不合规。
目录名**必须先**按 `YYYY-MM-DD-主题` 校验（体检的命名检查就是照这条判的，脚手架不拦就会立刻造出一个 ❌）。

## 六、`bootstrap.sh`

```bash
bash scripts/bootstrap.sh --root <新目录> [--name 名字] [--preset none|dsh|hithink] [--force]
```

补齐：六区目录与 README、`memory/settings.md`、`exchange/_TEMPLATE/`、`AGENTS.md`（模板）、
`.memory-kit.toml`（按 preset 生成）、`scratch/memory-tooling/` 薄壳与采集器，
结尾**自动生成第一份 `STATE.md`**。
**只补不覆盖**：已存在的文件跳过；`--force` 先备份成 `*.bak-<时间戳>`。

**采集器由你自己带**：技能只自带一个通用示例（`collectors/example.py`，纯标准库、默认不登记）。
`--collector <文件>` 可重复，把项目专用的采集器拷进工作区并登记进 `.memory-kit.toml`：

```bash
bash bootstrap.sh --root <工作区> --collector /path/to/my_collector.py
```

技能**不附带任何项目专用采集器** —— 那类东西依赖具体的 harness 或外部 CLI，属于工作区自己管
（需要外部命令时，采集器要先判断"在不在"，不在就如实写一句）。

铺完记得填 `AGENTS.md` 的定位 —— 没填时体检会给一条 ⚠️（`placeholders` 检查），别把 ⚠️ 当成 ❌0 就等于铺好了。

## 七、技能放哪 —— 一处即可，就地改

制度是**自然语言**的规则；`scripts/`、`templates/` 只是**参考实现**。放置原则只有一条：

- **技能本体只放一处**（clone、解压或包管理器装的都行），让 harness 能找得到它 ——
  多数框架扫描自己的"技能目录"，**具体路径因 harness 而异**；
- 工作区里的 `scratch/memory-tooling/*` 是**薄壳**：先看环境变量 `MEM_KIT_HOME`，
  再看铺开时填进文件的本机路径 ⇒ **换机器、换 harness 只要重跑一次 `bootstrap.sh`**；
- **改逻辑只改技能那一份**，别在薄壳里改；改完即生效，没有同步步骤。

> 有的 harness 用**自己的清单**判定技能是否可用（清单里没有的 slug 会被当成"不存在"）。
> 那类清单的字段与位置**因 harness 而异**，按你环境的文档来即可 —— 制度本身不依赖它：
> 有了薄壳（或 `MEM_KIT_HOME`），体检、STATE、索引都能跑。

## 八、`memory_query.py`（索引 / 检索 / 结账）

**它解决的问题**：旧规则要求"每篇笔记必须在 README 里列一行"，README 就随条目数无限膨胀 ——
实测（18 篇/天）**5 天撞 150 行触发线、8 天撞 200 行硬上限**，与"单篇必须压缩"结构性互斥。
现在：**台账进 JSON（数据，不参与 md 行数/断链规则）、README 只放规则 + 活窗口、检索交给程序**。

```bash
python3 scripts/memory_query.py --root <工作区> --rebuild        # 扫磁盘重建/刷新（合并：人工字段一律保留）
python3 scripts/memory_query.py --root <工作区> --check          # 索引 ↔ 磁盘 双向一致（体检调它）
python3 scripts/memory_query.py --root <工作区> --refresh        # 重生成各区 README 的活窗口（有界）
python3 scripts/memory_query.py --root <工作区> --stats          # 正文总量 vs 预算（防止"想记住一切"）
python3 scripts/memory_query.py --root <工作区> --since 2026-09-01 --grep 关键词 [--fulltext] [--format paths]
python3 scripts/memory_query.py --root <工作区> --tag 记忆制度 --status open --limit 20
python3 scripts/memory_query.py --root <工作区> --stale 30       # 超期未结项
python3 scripts/memory_query.py --root <工作区> --delete --path memory/2026-09-20/xx.md
python3 scripts/memory_query.py --root <工作区> --prune --before 2026-08-01 [--apply]   # 默认干跑
```

- **索引位置**：`memory` → `memory/index/YYYY-MM.json`（月片）；其他区 → `<区>/index.json`。
- **条目字段**：`path/zone/kind/date/title/summary/lines/sha256/mtime`（自动）+ `desc/refs/remark/tags/status/absorbed_into`（人工，重建时**继承**）。
  人工字段可在**正文里**用一行 `> tags: a, b` / `> status: absorbed` / `> absorbed-into: handbook/x.md` 声明，正文优先。
- **删除 = 顺着索引删**：`--delete` 默认 `mv` 到 `trash/<区>/…`（工作区口径 `mv` 不 `rm`）并**同步重建索引**；
  `--hard` 才真删。`--prune` 是批量版，**默认只列不删**，要 `--apply`；默认只动 `kind=note`。
- **活窗口**：各区 README 里 `<!-- index:start … -->` 到 `<!-- index:end -->` 之间的表格由 `--refresh` 生成
  （memory = 近 `live_days` 天 + 未结项，最多 `live_rows` 行）；**别手改**，它保证 README 有界。
- **预算**：`.memory-kit.toml` 的 `[index] budget_lines`（默认 6000 行）—— 正文总量才是**阅读面**；
  超预算体检会 ⚠️，提示 `--stats` 看分布、`--prune` 结账。



## 九、升级与自检

- 改完脚本：`python3 scripts/memory_doctor.py --root <技能目录> --only secrets`
  （技能自身也要干净，别把 Key 带进技能）。
  ⚠️ 对技能目录跑 `--only links` 会报 `templates/*` 里的一堆断链 —— **这是正常的**：模板里的相对链接
  要铺到工作区之后才有意义；技能自检只跑 `--only secrets`。
- 改完模板：跑一次 `bootstrap.sh --root /tmp/试铺 --preset hithink`，再对新目录跑全量体检，
  确认新工作区开局就是 ❌ 0（除了 `STATE.md` 未生成这类 ⚠️）。
- 版本号在 `VERSION`；体检输出头部会打印引擎版本，便于确认工作区用的是哪一版。
