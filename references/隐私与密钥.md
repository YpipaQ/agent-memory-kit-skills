# 隐私与密钥

## 一、硬规则

1. **一个 Key 只有一个出处**：要么用户级凭据文件（`chmod 600`），要么 `memory/settings.md` 且被显式豁免。
   别的地方**只写"去哪读"**。
2. **不进**脚本、命令参数、日志、报错、`STATE.md`、`exchange/task.md`、外部副本。命令行参数会进
   `ps`/shell history，也算泄露面。
3. **打印只留掩码**：前 6 位 + `…` + 后 4 位；体检命中时也只打印掩码，不把完整值写进日志。
4. **豁免要人确认**：`memory_doctor.py` 默认 `allow_files = []`，任何文件里的凭据都是 ❌。
   要放行必须在 `.memory-kit.toml` 里写明，并在那个文件里说明**为什么只有它能放**。
5. 发现 Key 进了不该进的地方：**当作已泄露处理** —— 先轮换，再清理，并记进 `memory/`（写结论，不写值）。

## 二、项目的可见性分级与推送闸门

**可见性在建项目/建卡时就要定**，默认最保守。三级：

| 级别 | 含义 | 建之前做什么 |
| --- | --- | --- |
| **仅本机**（默认） | 没有远端 | 什么都不用做；`git init` **照建**（本机建库 ≠ 外发；保密的东西更需要能回退） |
| **私有远端** | 只有自己看得到 | 先扫敏感串；**默认建 private** |
| **公开远端** | 全世界可见，**不可逆** | 用户**明确同意** ＋ 扫敏感串（含**历史**）＋ 确认没有密钥/内网地址/个人隐私 |

**闸门（推任何远端前）**：

1. **扫当前文件**：脚本的敏感串检查（`--only secrets`）跑一遍，0 命中。
2. **扫将推送的历史**：历史里的一次误提交，之后删掉**仍然在 `git log -p` 里**。
   做法（任何能读 git 的方式都行）：列出将推送的那段提交（`git rev-list <旧>..<新>`），
   逐提交把内容喂给同一套正则；命中就停，别推。
   ⚠️ 别用 `git grep A..B` 之类的"区间"写法当历史扫描 —— 它不按提交逐个走，会**静默漏过**。
3. **真实凭据值再对一遍**：正则只认"长得像 Key"的东西；把**已知的真实值**（本机凭据文件里的）
   拿来在树里搜一遍，才算查过。
4. **挂钩子只是防手滑**：一个 `pre-push` 钩子能把上面几步自动化，但任何钩子都能被环境变量绕过，
   也覆盖不到"在别的机器上推"。真正的保证是**推之前你看过扫描结果**。
5. **公开要人点头**：删仓库、重写历史都救不回已经被抓取/镜像/进搜索引擎的内容 ——
   所以"建 private"是默认，"建 public"必须用户明确同意。

> **判断顺序**：先问"这东西泄露了会怎样"，再定级别；不是"听起来重不重要"。
> 经验上**最大的泄露路径不是 git，而是把秘密贴给了不该给的模型或服务** —— 分级要连这条一起管。

## 三、能放凭据的地方

| 位置 | 权限 | 适用 |
| --- | --- | --- |
| `~/.<app>/credentials.env` | `0600` | 主用：CLI / SDK 读环境变量 |
| harness / 应用自己的凭据文件 | `0600` | 例如某个 harness 的统一凭据文件（**位置因环境而异**，按它的文档来） |
| `memory/settings.md` | 仓库内 | 仅当该服务没有用户级凭据文件可用；**必须在 `.memory-kit.toml` 豁免** |

## 四、扫描

```bash
python3 scripts/memory_doctor.py --root <工作区>                 # 全量体检，含敏感串
python3 scripts/memory_doctor.py --root <工作区> --only secrets   # 只查敏感串
python3 scripts/memory_doctor.py --root <技能目录> --only secrets # 技能本身也要干净
```

当前 6 类规则：形如 `hex32.alnum` 的 API Key、`sk-` 前缀、PEM 私钥头、AWS `AKIA`、
GitHub Token、JWT。**正则查不出"没有固定格式的密码"** —— 那类只有靠约定（只放凭据文件）。

扫不到的盲区（要人盯）：

- 无固定格式的口令 / 内网地址 / 个人信息；
- 二进制与压缩包（脚本按扩展名跳过，不当文本读）；
- **图片、截图、录屏**里出现的 Key；
- `~/.bash_history`、shell 配置文件、编辑器备份 —— 这些在工作区之外，脚本不管。

## 五、对外发布 / 拷外部介质前的检查单

- [ ] `--only secrets` 干净；
- [ ] 逐文件 `sha256sum -c`，要更强就 `dd iflag=direct` 绕过页缓存真读设备；
- [ ] 目标介质上的**目录名与本地可能不同名**，改名/对齐前先把事实写清楚（别把文档改成盘上没有的路径）；
- [ ] 拷完把核验结论写进 `archive/README.md` 的「外部副本」表（介质、路径、结果、日期）；
- [ ] 内网地址 / 主机名 / 用户名是否也属于不该外发的信息。

## 六、`git init` 前置检查单

- [ ] 明文 Key 已移出仓库（改到应用/harness 自己的用户级凭据文件），且该文件在 `.gitignore` 里；
- [ ] `.gitignore` 覆盖：凭据（`.env*`、`*.pem`、`*.key`、`credentials*`、`secrets*`、`.npmrc`、`.netrc`）、
  私钥（`id_rsa*`、`id_ed25519*`）、虚拟环境（`.venv*`）、构建产物（`build/`、`dist/`、`*.egg-info/`、
  `__pycache__/`）、缓存目录、`trash/`；
- [ ] 可见性**当场定**（默认"仅本机"）；`git init` 只是本机建库，**不外发**；
- [ ] `git add` 前跑 `--only secrets`；
- [ ] 真要推远端时走 [第二节的闸门](#二项目的可见性分级与推送闸门)（按提交扫历史，别用区间写法）；
- [ ] 若历史里已经有泄露：那个 Key **一律当作已泄露处理 —— 先轮换**（重写历史救不回别人手里的副本）；
- [ ] 仓库里的 `settings.md` 只留"去哪读"，不留值。

> **`git init` 之前和之后都不装 `pre-commit`**：它挡的是"提交"，而本制度要挡的是"**外发**" ——
> 本机提交是回退能力，不该被拦。闸门装在**推**这一步就够了。

## 七、体检脚本的设计取向

- **默认严格**：宁可误报 ❌，也不因为"大概是自家文件"就放过。
- **豁免显式**：豁免清单在配置里，看得见、可评审，不藏在脚本常量中。
- **只报可操作的问题**：不说"注意安全"，说"哪个文件哪一行命中哪类规则（掩码）"。
