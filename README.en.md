# agent-memory-kit-skills

**A workspace memory system for long-running AI collaboration.** Short rules, every fact written
once, volatile numbers generated by scripts — any new session rebuilds its context from a single
navigation table.

[中文](README.md) ｜ [Issues](https://github.com/YpipaQ/agent-memory-kit-skills/issues) ｜ Version 2.0.1 ｜ MIT

---

## What it is

Chat history is not memory. Compress a session, open a new window, hand the work to another
agent — and everything decided so far has to be re-established from scratch.

This kit moves what should be remembered **onto disk, in layers**, so that:

- a fresh session rebuilds context by reading one navigation table in `AGENTS.md`;
- a fact lives in exactly one file, and everything else links to it;
- numbers that change often are generated, never typed;
- when two people (or two agents) collaborate, *who wrote what and how far it was verified* stays
  auditable instead of resting on mutual trust.

It is plain Markdown plus scripts: no framework, no service, no runtime to keep alive.

## The six failure modes it targets

| How long-running work usually breaks | What this does instead |
| --- | --- |
| The same fact lives in several files; you update one and forget the rest | Every fact is written once; the rest link to it |
| The hot file grows without limit, and it is injected on every step | Hot memory keeps only rules and navigation; facts move out |
| Notes only accumulate until you try to remember everything | Ledgers are separated from prose and read by scope |
| The index lives in a human-readable doc and eventually blows the line limit | The ledger moves to JSON; the README keeps rules plus a constant-size live window |
| Nobody owns verification, so authorship of a conclusion is unclear | Questions and answers go through the `exchange/` protocol |
| The same thing is stored in several places and the copies drift apart | One true copy plus a registration card; sync machinery is retired |

## Quick start

```bash
git clone https://github.com/YpipaQ/agent-memory-kit-skills.git
KIT="$PWD/agent-memory-kit-skills"

# Lay the system down in a new workspace (six zones by default;
# add projects/ and data/ when you need them)
bash "$KIT/scripts/bootstrap.sh" --root /path/to/new-ws --name my-workspace

# Health-check it until no ❌ remains
python3 "$KIT/scripts/memory_doctor.py" --root /path/to/new-ws
```

`bootstrap.sh` also drops four **thin shells** into `scratch/memory-tooling/` — `memory_doctor.py`,
`state_snapshot.py`, `memory_query.py`, `new_exchange.sh`. They forward to the implementation shipped
with the skill, so the logic exists once: **don't edit logic inside the shells.**

## What you get

**Six zones** (the default; `projects` and `data` are common add-ons):

| Zone | What goes there |
| --- | --- |
| `memory/` | Work in progress, conclusions, failed attempts, todos — the prose you **read** |
| `handbook/` | Procedures and parameters that are settled, tested and repeatable — what you **follow** |
| `exchange/` | Controlled question-and-answer runs between agents — what you **hand over** |
| `scratch/` | Rerunnable scripts, benchmarks, artifacts — what you **run** (and may discard) |
| `archive/` | Snapshots that would roll out of the window and cannot be regenerated — what you **keep** |
| `trash/` | Artifacts you are done with; `mv`, never `rm` — what you **drop** |

**Three layers of content** — the part that actually prevents drift:

| Layer | File | What it holds | How it changes |
| --- | --- | --- | --- |
| Hot | `AGENTS.md` | Prompts, rules, long-term habits, the navigation table | By hand; keep it short |
| Semi-stable | `memory/settings.md` | Endpoints, where credentials live, paths, model names, gotchas | By hand |
| Volatile | `STATE.md` | Sizes, line counts, caches, archives, disks, devices | **Script-generated — never by hand** |

**The ledger is data; the README is rules.** A one-line-per-entry ledger kept in a human-readable
README grows with every entry and will eventually hit the line limit. So the ledger goes into
`memory/index/YYYY-MM.json` — machine-read, a few hundred KB even at thousands of entries — while
the README keeps the rules and a script-generated live window of constant size. Full text is always
kept: the index exists so you *read by scope by default*, not so you can delete things.

**Projects: one true copy plus a card** (the recommended shape once `projects/` is mounted; driven by
`[projects]` in `.memory-kit.toml`):

- **one true copy** — code, tests and artifacts live there (`embedded`: `projects/<name>/`;
  `card`: outside the workspace under `truth_root/<name>/`) and **edits happen only there**;
- the workspace keeps a **registration card of ≤40 lines** (true-copy path, kind, visibility, status,
  git, pointers — no code, no copied instructions);
- **judgement calls — create it? publish it? retire it? — are not encoded in scripts**; see
  [`references/项目管理.md`](references/项目管理.md) (natural-language guidance). The `cards` check
  only verifies **form**: the card exists, its path resolves, no true copy is left unregistered.

## Commands

Replace `<workspace>` with your workspace path and the script paths with wherever you installed the skill.

| Goal | Command |
| --- | --- |
| Health-check a workspace | `python3 scripts/memory_doctor.py --root <workspace>` |
| Secret-like strings only | `python3 scripts/memory_doctor.py --root <workspace> --only secrets` |
| Registration cards vs. true copies | `python3 scripts/memory_doctor.py --root <workspace> --only cards` |
| Generate the volatile-numbers snapshot | `python3 scripts/state_snapshot.py --root <workspace>` |
| Ledger: rebuild / verify / live window / size | `python3 scripts/memory_query.py --root <workspace> [--rebuild\|--check\|--refresh\|--stats]` |
| Scoped search / retire entries | `python3 scripts/memory_query.py --root <workspace> [--since D --grep word \| --stale 30 \| --delete --path P \| --prune --before D --apply]` |
| Create an exchange directory | `bash scripts/new_exchange.sh --root <workspace> "YYYY-MM-DD-topic" "description"` |
| Lay down the zones | `bash scripts/bootstrap.sh --root <new-dir> [--areas memory,...,projects,data] [--collector <collector.py>] [--name name]` |
| Keep true copies outside the workspace | `bash scripts/bootstrap.sh --root <new-dir> --areas memory,...,projects --projects-mode card --truth-root /path/to/truth-root` |

Exit codes: health check `0` clean / `1` has ❌; `--check` `0` consistent / `1` inconsistent;
`new_exchange.sh` `2` already exists / `3` template missing / `4` invalid directory name.

## Install

The skill is **harness-agnostic**: plain Markdown plus scripts. If your environment reads
`SKILL.md`, it works. Pick whichever fits:

1. **Drop it in** — put the whole `agent-memory-kit-skills/` directory into your skills folder
   (for example `~/.claude/skills/agent-memory-kit-skills/` in Claude Code, or `~/.dsh/skills/`
   in DSH) and restart the session. No package manager involved.
2. **npm** —

   ```bash
   npm install agent-memory-kit-skills
   ```

   then link or copy `node_modules/agent-memory-kit-skills` into your skills folder.
3. **Symlink** — keep the skill in one place and link it into the skills folder. The shells carry no
   hard-coded paths; re-running `bootstrap.sh` fills in the right paths for the current environment.

## Design notes

- **The skill knows nothing about your project.** Project differences live in
  `<workspace>/.memory-kit.toml`: zone list, thresholds, secret exemptions, STATE collectors.
- **Strict by default.** Secret-like strings are ❌ unless explicitly exempted — an exemption is a
  decision a human confirms, not a default the script is generous about.
- **Read-only collectors.** A collector never modifies what it collects; probes with side effects
  are blocked up front.
- **Thin shells, not copies.** Command entry points stay in the workspace; the implementation exists once.
- **Zero third-party dependencies.** Python 3 standard library (≥ 3.8; `tomllib` when available, a
  minimal built-in TOML subset otherwise) plus a POSIX shell. The default config ships
  `[state] tools = []` and calls no external program; when a number cannot be probed it says so
  instead of writing a plausible fake.
- **The check catches form, not facts.** Facts need real runs and cross-verification through `exchange/`.
- **Scripts are a reference.** The rules are the product — rewrite the scripts with your own tools
  if you prefer.

## Boundaries

- It does not judge whether your **content is correct** — the health check inspects structure
  (dead links, index consistency, size, secrets, protocol form).
- It never touches real data: collectors are **read-only**.
- It does not force filename conventions: **existing files keep their names**; rules govern new writes.
- It does not decide for you: whether to create, publish or retire a project is advice, not enforcement.

## Privacy

This repository **contains no credentials**; every template is a placeholder. Self-check:

```bash
python3 scripts/memory_doctor.py --root . --only secrets
```

Details: [`references/隐私与密钥.md`](references/隐私与密钥.md) (Chinese).
