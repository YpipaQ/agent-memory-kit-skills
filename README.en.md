# agent-memory-kit

**A memory system for directories where you work with an AI over the long haul.**
Short rules, every fact written once, numbers generated by scripts — a new session
rebuilds its context from a single navigation table.

[中文](README.md) ｜ [GitHub](https://github.com/YpipaQ/agent-memory-kit-skills) ｜ Version 1.3.1 ｜ MIT

---

## Why this exists

Chat history is not memory. The moment a session is compressed or you switch windows,
everything you did, tried and decided has to be asked for all over again.

This kit splits what should be remembered long-term into layers on disk. Any new session
can rebuild its context by reading the navigation table in `AGENTS.md`, and when two
people — or two agents — collaborate, who wrote what and how far it was verified stays
auditable instead of resting on mutual trust.

It is aimed at five familiar failure modes:

| The way it usually breaks | What this does instead |
| --- | --- |
| The same fact lives in several places; you update one and forget the rest | Every fact is written once; everything else links to it |
| The hot file grows and grows (it gets injected every time) | The hot file holds only rules and navigation |
| Notes only accumulate — you end up trying to remember everything | Ledgers are separated from prose and read by scope |
| The index lives in a human-readable doc and eventually blows the line limit | The ledger moves to JSON; the README keeps rules plus a live window |
| Nobody owns verification, so authorship of a conclusion is unclear | Questions and answers go through the `exchange/` protocol |

## Quick start

```bash
# 1) Get it
git clone https://github.com/YpipaQ/agent-memory-kit-skills.git
KIT="$PWD/agent-memory-kit-skills"

# 2) Lay the system down in a new workspace (six zones by default; projects and data are optional add-ons)
bash "$KIT/scripts/bootstrap.sh" --root /path/to/new-ws --name my-workspace

# 3) Run the health check until there are no ❌ left
python3 "$KIT/scripts/memory_doctor.py" --root /path/to/new-ws
```

The workspace now contains four **thin shells** under `scratch/memory-tooling/` —
`memory_doctor.py`, `state_snapshot.py`, `memory_query.py` and `new_exchange.sh`. They forward
to the implementations shipped with the skill, so there is exactly one copy of the logic:
**don't edit logic inside the shells.**

## What you get

**Six zones** (the default; `projects` and `data` are common add-ons):

| Zone | What goes there |
| --- | --- |
| `memory/` | Work in progress, conclusions you reached, failed attempts, todos — the prose you **read** |
| `handbook/` | Procedures and parameters that are settled, tested and repeatable — the quick reference you **follow** |
| `exchange/` | Controlled question-and-answer runs between agents — the words you **hand over** |
| `scratch/` | Rerunnable scripts, benchmarks, artifacts; anything not yet confirmed as long-term lives here — the things you **run** |
| `archive/` | Data snapshots that would otherwise be pushed out of the rolling window and cannot be regenerated — data you **keep** |
| `trash/` | Artifacts you are done with; `mv`, never `rm` — the things you **drop** |

**Three layers of content** (this is what keeps it from drifting):

| Layer | File | What it holds | How it changes |
| --- | --- | --- | --- |
| Hot | `AGENTS.md` | Prompts, rules and long-term habits plus the navigation table | By hand, as short as possible |
| Semi-stable | `memory/settings.md` | Endpoints, where keys live, paths, model names, known gotchas | By hand |
| Volatile | `STATE.md` | Sizes, line counts, caches, archives, disks, devices | **Generated by a script — never edited by hand** |

**The ledger is data; the README is rules.** A one-line-per-entry ledger kept inside a
human-readable README grows with every entry and will eventually hit the line limit. So the
ledger goes into `memory/index/YYYY-MM.json` — machine-read, a few hundred KB even at
thousands of entries — while the README keeps only the rules and a script-generated "live
window" of constant size. The full text is always kept: the structured index exists so you
read only what you need by default, not so that you can delete things.

## Layout

```
agent-memory-kit/
├── SKILL.md                 # Skill entry: rule summary + navigation + workflow (~150 lines)
├── README.md / README.en.md # Chinese / English documentation
├── references/              # Details: memory system / exchange protocol / privacy & secrets / tools & scripts / review notes
├── scripts/
│   ├── _common.py           # Shared: find the workspace root, read config, report
│   ├── memory_doctor.py     # Health check: dead links / index consistency / size / lead-with-conclusion / secrets / protocol / naming
│   ├── memory_query.py      # Ledger: rebuild / verify / refresh the live window / scoped search / size
│   ├── state_snapshot.py    # Generates STATE.md (the single source of volatile numbers)
│   ├── new_exchange.sh      # Create a controlled exchange (question) directory
│   ├── bootstrap.sh         # Lay the system down in a new workspace
│   └── collectors/example.py# Example collector: read-only; add or remove per project
├── templates/               # AGENTS.md, settings, per-zone READMEs, exchange, thin-shell templates
├── VERSION
└── package.json
```

## Commands

Replace `<workspace>` with your workspace path, and the script paths with wherever you put the skill.

| Goal | Command |
| --- | --- |
| Health-check a workspace | `python3 scripts/memory_doctor.py --root <workspace>` |
| Secrets only (before publishing or copying to removable media) | `python3 scripts/memory_doctor.py --root <workspace> --only secrets` |
| Generate the volatile-numbers snapshot | `python3 scripts/state_snapshot.py --root <workspace>` |
| Ledger: rebuild / verify / live window / size | `python3 scripts/memory_query.py --root <workspace> [--rebuild\|--check\|--refresh\|--stats]` |
| Scoped search / retire entries | `python3 scripts/memory_query.py --root <workspace> [--since D --grep word \| --stale 30 \| --delete --path P \| --prune --before D --apply]` |
| Create an exchange directory | `bash scripts/new_exchange.sh --root <workspace> "YYYY-MM-DD-topic" "description"` |
| Lay down the zones | `bash scripts/bootstrap.sh --root <new-dir> [--areas memory,...,projects,data] [--collector <collector.py>] [--name name]` |

Exit codes: health check `0` clean / `1` has ❌; `--check` `0` consistent / `1` inconsistent;
`new_exchange.sh` `2` already exists / `3` template missing / `4` invalid directory name.

## Wiring it into your harness

The skill is **harness-agnostic**: plain Markdown plus scripts, effective as soon as the
environment reads `SKILL.md`. Pick whichever fits:

1. **Drop it in (simplest)**: put the whole `agent-memory-kit/` directory into your skills
   folder — for example `.agent/skills/agent-memory-kit/` or `~/.dsh/skills/agent-memory-kit/`.
   Restart the session. **No npm needed.**
2. **npm**:

   ```bash
   npm install agent-memory-kit-skills
   ```

   Then link or copy `node_modules/agent-memory-kit-skills` into your skills folder.
   ⚠️ **Why the package name carries a `-skills` suffix**: the skill itself is called
   `agent-memory-kit`, but that name is already taken on npm by **somebody else's package**,
   so the published name got a suffix. `npm install agent-memory-kit` will *not* get you this
   project — don't install the wrong one.
3. **Symlink**: keep the skill in one place and link it into your harness's skills directory
   (the path depends on your harness). The shims carry no hard-coded paths, so re-running
   `bootstrap.sh` is enough to point them at this machine.

## Design tradeoffs

- **The skill knows nothing about your project**: every project difference lives in
  `<workspace>/.memory-kit.toml` (zone list, thresholds, secret exemptions, STATE collectors).
- **Strict by default**: secret-like strings are ❌ unless explicitly exempted — an exemption is a
  decision a human confirms, not a default the script is generous about.
- **Read-only**: collectors never modify what they collect; probes with side effects are blocked first.
- **Thin shells, not copies**: command entry points stay in the workspace; the implementation exists once.
- **Zero dependencies**: the Python 3 standard library (≥ 3.8; `tomllib` when available, a minimal
  built-in TOML subset otherwise) plus a POSIX shell. The default config ships `[state] tools = []`
  and **runs no external programs**; when a platform number can't be probed it says so honestly
  rather than writing a plausible-looking fake.
- **The check catches form, not facts**: facts need real runs and cross-verification through `exchange/`.

## Boundaries (what it does not do)

- It won't judge whether your **content is correct** — the health check only inspects structure
  (dead links, index consistency, size, secrets, protocol form).
- It never touches real data: collectors are **read-only**.
- It doesn't force filename conventions: **existing files keep their names**; the rules govern new writes.
- It isn't tied to an implementation: the scripts are a reference — **the rules are the product**,
  and you can rewrite the scripts with your harness's native tools.

## Privacy

This repository **contains no credentials**; every template is a placeholder. Self-check:

```bash
python3 scripts/memory_doctor.py --root . --only secrets
```
