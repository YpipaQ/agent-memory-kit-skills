# 试验台（scratch）

**这里放"能再跑一遍"的东西**：探针、基准实现、复现脚本，以及它们产生的原始产物。

和另外几个区的分工：

| 区域 | 放什么 | 判断标准 |
| --- | --- | --- |
| `memory/` | 在办的事、试验记录、索引（＋常驻 `settings.md`） | **要读**的叙述 |
| **`scratch/`** | 可复跑的脚本 + 脚本产物 | **要跑**的东西 |
| `handbook/` | 已定型、可照做的流程与结论 | **可照做**的速查 |
| `exchange/` | 出题/作答的受控交流 | **要传**的话 |
| `archive/` | 会被滚动窗口挤掉、不可再生的数据快照 | **要留**的东西 |
| `trash/` | 用过且不会再读的产物 | **要扔**的东西 |

## 规则

- 目录结构：**`scratch/<种类>/`** —— 按**任务种类**命名，**不带日期**。
  例：`scratch/memory-tooling/`、`scratch/<某基准>/`。同一类的新脚本/新版本**就地加文件，或让文件名带日期**
  （如 `probe-2026-10-01.py`），不再新建日期目录。
- 放进来：可复跑的探针/基准脚本、复现步骤、脚本自己生成的原始产物（JSON/日志）。
- 不要放：结论与叙事（→ `memory/`）、Key 明文或私人数据（脚本只从凭据/env 读）、
  一次性且不会再跑的产物（→ `trash/`）。
- 脚本自查三条：**自带短超时**（防上游挂起）、**能自校验**（打印结果与期望值对比，别只打印数字）、
  **不回显凭据**。
- **为什么留**：让后来者用小代价复核贵步骤 —— 一份毫秒级基准脚本，能替掉一次几十秒的付费模型调用。
  所以**存可复跑的产物，比存贵步骤的结论更值**。
- 清理：整个 `scratch/` 删掉不影响任何配置与记忆。但**被 `memory/` 引用的脚本，删前先改对应文档**，
  否则冷记忆里会留下断链。
