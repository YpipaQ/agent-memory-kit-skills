# 项目区（projects）

**这里放"要构建、要长期演进"的项目**：源码、测试、构建产物，以及项目自己的 `README.md`。

> **准入门槛**：新东西**默认先放 [`../scratch/`](../scratch/README.md)**（可复跑、整区可弃）；
> **只有确认要长期维护**，才"毕业"迁进本区。与 `scratch/` 相反，**本区不能整区删除**。

判据是**你要拿它做什么** —— 与其余各区的唯一区别：

| 区 | 判据 |
| --- | --- |
| `memory/` | **要读**的叙述（在办、结论、原始输出） |
| `handbook/` | **可照做**的速查 |
| `scratch/` | **要跑一次**的探针 / 基准 / 复现脚本（**默认落脚点**） |
| **`projects/`** | **要开发**、会持续维护的东西 |
| `exchange/` | **要传**的话（多智能体出题 / 作答） |
| `archive/` | **要留**的不可再生快照 |
| `trash/` | **要扔**的 |

## 规则

- 目录结构：**`projects/<项目名>/`** —— 按**种类**命名、**不带日期**；项目名一旦定了别改，
  改名要同步改所有引用（体检查断链）。
- **每个项目自带 `README.md`**：这是什么 / 怎么跑 / 依赖什么 / 当前状态 / 最后验证日期。
- **项目里只放"能跑、能构建"的东西 + README**。项目的过程、结论、踩坑写 `memory/YYYY-MM-DD/`；
  项目 README **只放相对链接**指过去，**不复制结论**（防"同一句话两处写、改一处忘一处"）。
- 项目可以有自己的 `.git`；**不要把整个工作区 `git add`**。
- 本区里若放了**别处的树**（某个技能 / 模板仓库的检出），它的相对链接按自己的布局解析、
  在工作区里必然断 —— 在 `.memory-kit.toml` 的 `[scan] exclude` 里排除该路径，别让它污染体检。
