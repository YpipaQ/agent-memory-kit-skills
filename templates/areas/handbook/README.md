# 手册区（handbook）—— 已定型内容的速查

**这里放"已经彻底完善、可以直接照做"的流程与结论**。定位是**快速参考**：进来就查，不读过程史。

与其它区的分工：

| 区域 | 放什么 | 判断标准 |
| --- | --- | --- |
| `memory/` | 当天做过什么、试出什么、还没定的事 | **在办**的工作记录 |
| **`handbook/`** | 已定型且**实测通过**的流程 / 结论 / 参数表 | **可照做**的速查 |
| `scratch/` | 可复跑的脚本与产物 | **要跑**的东西 |
| `archive/` | 会被滚动窗口挤掉、不可再生的数据快照 | **要留**的数据 |
| `exchange/` | 出题/作答的受控交流 | **要传**的话 |
| `trash/` | 用过且不会再读的产物 | **要扔**的东西 |

## 准入条件（三条都满足才迁进来）

1. **定型**：不再处于试验/待定状态，步骤或结论已经稳定；
2. **实测通过**：写清验证日期与**验到哪一层**（逻辑层/文件层/设备层/新鲜度层）；
3. **有出处**：条目里给出 `memory/YYYY-MM-DD/...` 的来源链接与（若有）对应脚本路径。

迁进来的同时，**把来源笔记里已经定型的那部分压缩**（删掉过程史，只留"已迁往 handbook/xxx"的指针），
免得两处都成了真源。压缩时在笔记末尾留一行压缩记录：删了什么、去哪了。

## 命名与结构

- 一个主题一个文件：`handbook/<主题>.md`（**按主题命名，不带日期**）；
  同类内容**在同一个文件里改**，不要新建日期文件。
- 每个条目开头三行内要有：**结论 / 怎么做 / 坑**；超过 150 行必须压缩（同 `memory/` 的硬规则）。
- 文件里带一段 `最后验证：**YYYY-MM-DD**（验证到 X 层）` —— 体检会按它提醒复审（默认 90 天）。

## 索引

| 主题 | 文件 | 最后验证 | 来源 |
| --- | --- | --- | --- |
| <主题> | `<主题>.md` | <YYYY-MM-DD>（<验到哪一层>） | `memory/<日期>/<笔记>.md` |
