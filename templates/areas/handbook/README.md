## 两种状态 + 归并优先

- **主题卷宗（`状态：evolving`）**：一个主题一个文件，**可以先进来再慢慢定型**；结构只要求「结论 / 怎么做 / 坑」。
- **定稿（`状态：settled`）**：走下面三条准入，并标 `最后验证：YYYY-MM-DD（验到哪层）`。
- **归并优先于压缩**：同一主题散在多篇日期笔记时，先把结论**合并回主题卷宗**，再把来源笔记压成指针、
  标 `状态：absorbed` ＋ `已吸收：…`；**不要为消体检 ⚠️ 只改状态**，也不要把日志硬压成 80 行。
- 主题卷宗到触发线再压缩——这时压缩是"收拢坑"，才有意义。

## 准入条件（定稿三条）

1. **定型**：不再处于试验/待定状态，步骤或结论已经稳定；
2. **实测通过**：写清验证日期与**验到哪一层**（逻辑层/文件层/设备层/新鲜度层）；
3. **有出处**：条目里给出 `memory/YYYY-MM-DD/...` 的来源链接与（若有）对应脚本路径。

迁进/合并的同时，**把来源笔记里已经定型的那部分压成指针**（"已迁往 handbook/xxx"），
免得两处都成了真源；笔记末尾留一行压缩记录：删了什么、去哪了。

## 命名与结构

- 一个主题一个文件：`handbook/<主题>.md`（**按主题命名，不带日期**）；
  同类内容**在同一个文件里改**，不要新建日期文件。
- 每个条目开头三行内要有：**结论 / 怎么做 / 坑**；到触发线就归并/压缩（阈值见 `.memory-kit.toml`）。
- 定稿文件带 `最后验证：YYYY-MM-DD（验到 X 层）` —— 体检会按它提醒复审（默认 90 天）。
