# 留档区（archive）

**这里放"会被时间挤掉、需要长期留着"的原始数据**。分工见下表：

| 区域 | 放什么 | 判断标准 |
| --- | --- | --- |
| `memory/` | 在办的事、试验记录、索引（＋常驻 `settings.md`） | **要读**的叙述 |
| `handbook/` | 已定型、可照做的流程与结论 | **可照做**的速查 |
| `scratch/` | 可复跑的脚本 + 脚本产物 | **要跑**的东西 |
| `exchange/` | 出题/作答的受控交流 | **要传**的话 |
| **`archive/`** | **不可再生或会被滚动窗口挤掉的数据快照** | **要留**的东西 |
| `trash/` | 用过且不会再读的产物 | **要扔**的东西 |

## 规则

- 目录结构：**`archive/<种类>/<快照日期>/`** —— 顶层按**数据种类**，日期只作**快照标识**
  （例 `archive/<种类>/YYYY-MM-DD/`）。同类下一次快照新建日期子目录，**不覆盖**。
- 每个快照目录必须有：
  - 数据文件本身（推荐 **Parquet**：压缩好、类型化、DuckDB/pandas 都能读）；
  - `manifest.json`：来源、覆盖范围、行数、**sha256**、生成时间、还原办法；
  - `README.md`：这份归档**为什么存在**、能回答什么问题、以及坑；建议再附 `SHA256SUMS.txt`。
- 归档**只增不改**：同一区间不要覆盖重写，需要修正就新建日期目录并在 README 里说明取代关系。
- **为什么需要它**：上游给的常常是**滚动窗口**（只保留最近 N 年，全量重建时最老的部分被挤出去），
  所以"本地库/本地副本"**不等于归档**。想让老数据活下来，必须单独导出保存。
- 归档可以整份拷到外部介质（U 盘/网盘）。拷贝后**用 sha256 核对**（`sha256sum -c`）；
  要更强的证据就绕过页缓存真读设备（见下）。

## 索引

| 目录 | 内容 | 备注 |
| --- | --- | --- |
| `<种类>/<日期>/` | <覆盖范围、行数、体积> | <为什么留 / 会被什么挤掉> |

## 外部副本

| 介质 | 路径 | 状态 |
| --- | --- | --- |
| <U 盘/网盘、容量、文件系统> | <盘内路径> | <核对结果与日期；**盘上路径可能与本地不同名，改名前先对齐**> |

复核命令（**挂载状态下直接跑，不要先卸载**）：

```bash
cd <盘内目录> && sha256sum -c SHA256SUMS.txt
# 更强的：绕过页缓存，真读设备（否则 "通过" 可能只读到了缓存）
while read -r want name; do
  got=$(dd if="$name" iflag=direct bs=1M status=none | sha256sum | awk '{print $1}')
  [ "$got" = "$want" ] && echo "OK $name" || echo "MISMATCH $name"
done < SHA256SUMS.txt
```
