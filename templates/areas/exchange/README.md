# 交流区（exchange）—— 多智能体测试与联调

**这里放"一个智能体出题、另一个智能体作答"的受控交流**。核心是把**写入范围**说清楚：
出题方与作答方各自只碰自己那份文件，于是"谁写了什么"一目了然，复盘不需要猜。

> 这不是防着谁。信任不是靠限制建立的，但**并发的两个写入者会互相踩**，
> 而**事后无法归因的结论不能当结论用** —— 分工是为了这两件事。

## 协议（每次测试一套，缺一不可）

```
exchange/YYYY-MM-DD-主题/
├── task.md      # 测试文档：出题方写（自包含、可复现、含验收标准）
├── answer.md    # 答复文档：建目录时为空，只有作答方写
└── (可选) 附件：题目需要的输入文件、脚本、原始产物
```

| 角色 | 可以写 | 不要写 |
| --- | --- | --- |
| **出题方**（给测试的智能体） | `task.md`、附件、以及**全部记忆**（`memory/`、各索引、`handbook/`） | 测试进行中不要动 `answer.md`（否则分不清谁写的） |
| **作答方**（接测试的智能体） | **只有 `answer.md`** | 不改 `task.md`，不写记忆，不动其它文件 |

规则：

1. **`answer.md` 建目录时必须为空**。出题方可以放一行标题与"（待作答）"占位，其余等作答方写。
2. **作答方只写 `answer.md`**。题目不自包含、无法完成时：**在 `answer.md` 里写明卡点并停下**，
   不要反问式地改题 —— 出题方看到卡点会自己修题。
3. **结论由出题方复核后写进记忆**。作答方的回答不自动成为结论；复核要说清**验到哪一层**
   （逻辑层／文件层 sha256／设备层绕过页缓存／新鲜度层）。
4. `task.md` 必须写清：目标、输入与位置、**验收标准（怎么判定对错）**、允许的耗时/代价上限、交付物格式。
5. `answer.md` 里鼓励作答方写上"我不确定的点 / 建议的下一步"，**这不是越界**，是让复核更有价值。
6. 目录名 `YYYY-MM-DD-主题/`（**按时间**）；同类测试**在同一个目录里追加**
   （`task-2.md` / `answer-2.md`），不要一天建一堆新目录。

## 测试 ≠ 可用产物

交流区只存**测试过程与答复**（谁问、谁答、怎么验）。测试里产出的**可复用成果**要搬走：

| 产出 | 去哪 |
| --- | --- |
| 定型的流程 / 结论 / 参数表 | `handbook/` |
| 可复跑的脚本、基准、产物 | `scratch/<种类>/` |
| 需要长期留的数据快照 | `archive/<种类>/<日期>/` |
| 只是这次回答的证据 | 留在本目录 `answer.md`，不动 |

搬走后把 `task.md` 的状态改成 `absorbed`，并写上"结论已写入 XXX"。

## 状态怎么标

`task.md` 顶部放一行状态，出题方维护：

```
状态: pending | answered | verified | absorbed | abandoned
```

`pending` 已出题待作答；`answered` 作答方已交；`verified` 出题方复核过；
`absorbed` 结论已写进 `memory/` 或 `handbook/`；`abandoned` 放弃（要写原因）。

## 模板与脚手架

```bash
bash scratch/memory-tooling/new_exchange.sh "YYYY-MM-DD-主题" "简短说明"
```

脚本会建目录、拷模板、把 `answer.md` 留空，并打印出题方/作答方各自的可写范围。
模板另存一份在技能里（`agent-memory-kit/templates/exchange/`），没铺模板时脚本会回退到那里。

## 与 Agent Teams 的关系

用 Agent Teams 时，`team_task_create` 的 `write_scopes` 直接写 `exchange/YYYY-MM-DD-主题/answer.md`，
并在任务描述里指向 `task.md`；这样"共享任务板"与"交流区文档"互为凭据，谁越界写文件一眼能看出来。
